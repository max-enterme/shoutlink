# yt-redirect-pin テストのお願い

テストしてくれてありがとうございます。この文書だけで完結するように書いてあります。

---

## 1. これは何か

YouTube のライブ配信で**他のチャンネルからライブリダイレクトを受け取ったとき**に、
「◯◯さんからリダイレクトありがとうございます! (チャンネル URL)」をライブチャットへ自動で投稿し、
そのメッセージを固定する Chrome 拡張です。

**開発中です。**2026-08-05 に開発者の実配信で「検知 → 投稿 → 固定」が一通り動くことを
確認しましたが、**確認できたのは日本語 UI・Studio(ライブ管制室)のチャット・1 つの環境だけ**です。
別の環境で同じように動くかは分かっていません。そこを見てほしくてお願いしています。

送信元 URL を手で入力して実行するボタンも常設してあるので、**自動検知が動かない環境でも
投稿と固定は試せます。**

### 何をする拡張か(権限の説明)

- 動くのは **YouTube のライブチャットのページだけ**(`youtube.com/live_chat` と
  `studio.youtube.com/live_chat`)。それ以外のページでは一切動きません。
- 外部のサーバーとは通信しません。設定はブラウザ内 (`chrome.storage`) にだけ保存されます。
- **あなたがログインしているアカウントの名義でチャットに投稿します。** これが一番の注意点です。

> **本番の配信では使わないでください。** 必ず**自分の限定公開(または非公開)のテスト配信**で
> 試してください。投稿は実際にチャットへ流れます。

同梱の `source/` にソースコード一式が入っています。何をしているか気になったら見てください
(`source/src/` が実体、`source/public/manifest.json` が権限の宣言)。

---

## 2. 用意するもの

- Google Chrome(または Edge 等の Chromium 系)
- **自分のチャンネルのテスト配信**(限定公開でよい)。ライブチャットが開けて、
  自分でメッセージを固定できる状態
- 所要 15 分程度

---

## 3. インストール

1. この ZIP を適当な場所に**展開**する(展開せずに読み込むことはできません)
2. Chrome で `chrome://extensions` を開く
3. 右上の **「デベロッパー モード」** を ON にする
4. 左上の **「パッケージ化されていない拡張機能を読み込む」** をクリック
5. 展開したフォルダの中の **`extension` フォルダ**を選ぶ
6. `yt-redirect-pin` のカードが出れば完了

> Chrome が「デベロッパー モードの拡張機能を無効にする」という警告を毎回出すことがあります。
> 未署名の拡張なので正常です。「キャンセル」で閉じてください。

---

## 4. 設定を開く

`chrome://extensions` の `yt-redirect-pin` のカード → **「詳細」** → **「拡張機能のオプション」**
(別タブで開きます)。

**最初はこの状態にしてください:**

| 項目 | 最初の値 |
|---|---|
| 有効にする | **ON** |
| **自分のチャンネル** | **あなたの `@ハンドル`** ← 必ず入れてください(後述) |
| 投稿文テンプレート | そのまま(既定) |
| 固定モード | **`off`(固定しない)** ← まず投稿だけ確認する |
| クールダウン | `0` ← 何度も試せるように |
| 診断ログ | **ON** ← 何が起きたかコンソールに出ます |

> ⚠️ **「自分のチャンネル」は必ず設定してください。**
> リダイレクトを**送った**ときにも自分のチャットにバナーが出ます。それを「受けた」と
> 取り違えて投稿してしまう事故が実際に起きています。ここを設定しておくと防げます。

> **この拡張は `studio.youtube.com` のライブ管制室のチャットでしか動きません。**
> `www.youtube.com` のライブチャットは他人の配信でも開けてしまい、自分の配信かどうかを
> 判別できないためです。ポップアウトを使う場合も Studio 側のものを使ってください。

---

## 5. テスト

テスト配信を開始し、**YouTube Studio のライブ管制室**を開いてください
(`studio.youtube.com` → 「ライブ配信」)。**既定ではこの画面のチャットでしか動きません。**

チャット部分の**右下に「↩ 返礼」ボタン**が出ていれば、拡張が読み込めています。
**出ていない場合はここで止めて、その旨を報告してください。**

> `www.youtube.com` の watch ページやポップアウトでは、既定では**動きません**(意図的です)。
> コンソールに `この画面では動かさない: ...` と出ます。

### テスト A — 投稿(固定モード `off`)

1. 右下の **「↩ 返礼」** をクリック
2. 「送信元チャンネル URL / @ハンドル」に、適当なチャンネルの URL を入れる
   - 例: `https://www.youtube.com/@example`(実在するチャンネルなら何でも構いません)
   - `@ハンドル` だけでも受け付けます
3. 「表示名」は空のままでよい
4. **「投稿して固定」** を押す

**確認すること:**

- [ ] チャットに「◯◯さんからリダイレクトありがとうございます! (URL)」が投稿されたか
- [ ] 文面が崩れていないか(URL が切れている、名前が変、など)

### テスト A' — 固定だけ試す(投稿しない)

「↩ 返礼」のパネルの下のほうに **「固定だけ試す」** があります。**投稿せず**、チャットの
**最後のメッセージ**を固定するだけの切り分け用ボタンです(設定に関わらず上書きで固定します)。

1. チャットに何か 1 行、手で書き込む
2. 「固定だけ試す」を押す

- [ ] そのメッセージが固定されたか
- [ ] パネルに `固定結果: pinned` と出たか

`unavailable` と出たら、**その環境ではメニューから固定できていない**ということです。
コンソールの `メニューに「固定」項目が見つからない` の行を展開して送ってください。

### テスト B — 固定(固定モード `ifEmpty`)

1. オプションで**固定モードを `ifEmpty`** に変えて保存
2. **何も固定されていない状態**にする(固定中のメッセージがあれば解除しておく)
3. 「↩ 返礼」からもう一度実行する

- [ ] 投稿されたメッセージが**チャット上部に固定された**か

続けて、**固定されている状態のまま**もう一度実行する:

- [ ] 投稿はされるが、**さっきの固定はそのまま残っている**か(上書きされないのが正しい)

### テスト C — 固定(固定モード `always`)

1. 固定モードを **`always`** に変えて保存
2. 何かが固定されている状態で実行する

- [ ] 投稿されたメッセージが**既存の固定を上書きして**固定されたか

> `always` は既存の固定(告知など)を消します。テスト配信なので問題ないはずですが、念のため。

### テスト D — 止められるか

1. オプションで **「有効にする」を OFF** にして保存
2. 「↩ 返礼」から実行する

- [ ] **何も投稿されない**か(想定外の連投を止められることの確認です)

### テスト E — 連続実行の抑止

1. 「有効にする」を ON に戻し、**クールダウンを `60`** にして保存
2. **同じ URL** で 2 回続けて実行する

- [ ] 1 回目は投稿され、**2 回目は投稿されない**か
- [ ] **違う URL** なら投稿されるか

### テスト F — 呼び名の辞書

設定ページの **「呼び名の辞書」**。`{name}` に入る呼び名を、チャンネルごとに登録できます。

1. **＋** の行に `@example`(実在する適当なチャンネルの @ハンドル)と呼び名を入れて ＋ を押す
2. 「↩ 返礼」から**その同じチャンネル**で実行する

- [ ] 投稿文の名前が**登録した呼び名**になったか
- [ ] 登録していないチャンネルで実行すると、**ハンドルのまま**投稿されるか
- [ ] 実行した相手が一覧に**自動で追加**されるか(呼び名は空のまま)

### テスト G — 実際にリダイレクトを受けられる場合のみ

他のチャンネルから実際にライブリダイレクトを受けられる環境がある人だけ。
(送る側には登録者 1,000 人以上の要件があります。受け取り許可の既定は「登録しているチャンネル」なので、
送り手のチャンネルを登録しておく必要があります。)

- [ ] リダイレクトを受けたとき、**手を触れずに**投稿・固定されたか
- [ ] 受けてから投稿まで 10 秒以内だったか
- [ ] 投稿文の **URL をクリックして、送信元チャンネルへ実際に飛ぶか**
- [ ] 動かなかった場合 → 診断ログを ON にした状態のコンソールをそのまま送ってください

> 開発者の環境では、通知の文言は `@ハンドル とその視聴者が参加しました。挨拶しましょう。` でした。
> **文言が違っていたら検知できません。**その場合は通知の文面をそのまま教えてください。

## 6. ログの見方

拡張のログはブラウザの開発者ツールに出ます。

1. **ポップアウトしたチャットのウィンドウ**をクリックして選び、**F12** を押す
2. 「Console」タブを開く
3. `[yt-redirect-pin]` で始まる行が拡張のログです

正常な流れだとこう出ます:

```
[yt-redirect-pin] 起動した https://www.youtube.com/live_chat?...
[yt-redirect-pin] 投稿する (manual): ◯◯さんからリダイレクトありがとうございます! https://...
[yt-redirect-pin] 固定結果: pinned
```

`固定結果` の意味:

| 値 | 意味 |
|---|---|
| `pinned` | 固定した |
| `skipped` | 意図的に固定しなかった(`off`、または `ifEmpty` で既に固定があった) |
| `unavailable` | 固定しようとしたが**画面上の「固定」が見つからなかった** ← 報告してほしい |

## 7. 動かないときに送ってほしいもの

### (a) コンソールのログ

Console タブで右クリック →「Save as...」で保存するか、`[yt-redirect-pin]` の行をコピーして貼ってください。

### (b) 画面構造(DOM)— これが一番助かります

ライブチャットのウィンドウの Console に、以下を**1 行ずつ貼って実行**し、結果を送ってください。

**① ライブチャットで使われている部品の一覧:**

```js
[...new Set([...document.querySelectorAll('*')].map(e => e.tagName.toLowerCase()))].filter(t => t.startsWith('yt-live-chat'))
```

**② 「固定中」のバナーの構造(何かを固定した状態で実行):**

```js
[...document.querySelectorAll('*')].filter(e => /pinned|banner/i.test(e.tagName)).map(e => [e.tagName.toLowerCase(), e.id, e.textContent.trim().slice(0, 40)])
```

**③ メッセージのメニュー項目(自分のメッセージの ⋮ を手で開いた状態で実行):**

```js
[...document.querySelectorAll('[role="menuitem"], ytd-menu-service-item-renderer')].map(e => [e.tagName.toLowerCase(), e.textContent.trim()])
```

**④ リダイレクトを受けた場合のみ — 通知が出た直後に実行(クリップボードにコピーされます):**

```js
copy(document.querySelector('yt-live-chat-item-list-renderer')?.outerHTML)
```

> ⚠️ **④ の結果には、チャットにいる視聴者の名前や ID がそのまま入っています。**
> 送る前に、**チャンネル名・ハンドル・ID を適当な文字列に置き換えてください**
> (リダイレクトの送信元だけ分かれば十分です)。判断に迷ったら、置換せずに送るのではなく
> 先に相談してください。

## 9. 終わったら

`chrome://extensions` の `yt-redirect-pin` のカードで **「削除」** を押せば消えます。
設定も一緒に消えます。

テスト配信に投稿されたメッセージは、チャットから手で消してください。
