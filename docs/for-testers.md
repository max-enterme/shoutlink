# 返礼リンク (shoutlink) テストのお願い

テストしてくれてありがとうございます。この文書だけで完結するように書いてあります。

---

## 1. これは何か

YouTube のライブ配信で**他のチャンネルからライブリダイレクトを受け取ったとき**に、
「◯◯さんからリダイレクトありがとうございます! (チャンネル URL)」をライブチャットへ自動で投稿し、
そのメッセージを固定する Chrome 拡張です。

**開発中です。**2026-08-05 に開発者の実配信で「検知 → 投稿 → 固定」が一通り動くことを
確認しましたが、**確認できたのは日本語 UI・Studio(ライブ管制室)のチャット・1 つの環境だけ**です。
別の環境で同じように動くかは分かっていません。そこを見てほしくてお願いしています。

送信元 URL を手で入力して実行するボタンも常設してあるので、**自動検知が動かない環境でも
投稿と固定は試せます。**

### 自由文 (`{msg}`) について — 先に知っておいてほしいこと

送信元ごとに「その相手への一言」を登録しておくと、投稿文に差し込めるようになりました。
テストの前に、次の 2 点を知っておいてください。

> ⚠️ **送信元の検知は推測を含みます。取り違えると、その人に宛てて書いた一文が
> そのまま別の相手への投稿に載ります。** 呼び名の取り違えなら「誰かの名前」が出るだけですが、
> 自由文は宛先を間違えると内容そのものが事故になります。この拡張は送信元の取り違えを
> **過去に 2 回起こしています。** テストでも、**取り違えて別の人に読まれても困らない内容**
> だけを入れてください。

> ✅ **自由文入りの文面は 2026-08-23 の実配信で通しました。** 検知 → 投稿 → 固定まで、
> 自由文が載った状態で通ることを確かめています。

### コメント返し(この版で増えた 2 つ目の引き金)— 先に知っておいてほしいこと

**投稿の引き金が 2 種類になりました。**リダイレクトの受信に加えて、
**辞書で「コメントに反応する」を付けた人がチャットにコメントしたとき**にも投稿します。

> ⚠️ **既定は OFF です。**設定の「コメントに反応して投稿する」(既定 OFF) と、
> **辞書の行ごとのフラグ**(既定 OFF)の**両方を自分で入れない限り、この機能は動きません。**
> 何もしなければ、これまでと同じ挙動です。

> ⚠️ **ON にすると投稿の頻度が上がります。**コメントはリダイレクトより桁違いに多いためです。
> 歯止めは **同じ配信・同じ人に 1 回 / 最低 5 秒間隔 / 1 配信 20 件まで**の 3 つで、
> **どれも設定では変えられません。**

> ✅ **コメント返しは 2026-08-23 の実配信で通しました。**
> 登録した人のコメントで投稿されること・**固定されないこと**・同じ配信で 2 回目が出ないこと・
> **自分の投稿を引き金に再投稿しないこと**は確かめています。
>
> ⚠️ **残る 1 点: チャットを開き直したときに、過去のコメントへ一斉投稿しないか。**
> **3 重の歯止めがあり単体テストでも押さえています**が、**実 DOM では未確認**です。
> **この 1 点を見てもらえると助かります** — 登録した人のコメントが既にあるチャットで
> ページを再読み込みして、投稿が出なければ通過です。
> **試してもらえるなら、必ず限定公開のテスト配信でお願いします。**

**コメント返しは固定しません**(固定枠は 1 件しかなく、コメントのたびに上書きすると
リダイレクト返礼の固定が流れるため)。文面も**リダイレクト返礼とは別のテンプレート**で、
`{msg}` に入る自由文も**別のフィールド**です。

### 何をする拡張か(権限の説明)

- 動くのは **YouTube Studio のライブ管制室のチャットだけ**(`studio.youtube.com/live_chat`)。
  それ以外のページ(`www.youtube.com` のライブチャットを含む)には**そもそも読み込まれません**。
  `www` 側は他人の配信のチャットも開けてしまい、自分の配信かどうかを判別できないためです。
- **インストールすると、許可の表示に `studio.youtube.com` と `www.youtube.com` の 2 つが出ます。**
  役割が違います。
  - `studio.youtube.com` … **拡張が読み込まれて動くのはここだけ**(検知・投稿・固定)
  - `www.youtube.com` … **設定画面が、辞書に登録したチャンネルのページを 1 回だけ読みに行く**ため
    (コメントの投稿者と照合するチャンネル ID を控える)。**このページに拡張は読み込まれません。
    この取得を行うのは設定画面だけで、ライブチャットの画面では行いません**
- **開発者のサーバーとは通信しません。**外部へ送るデータはありません。上の 1 回の取得も
  YouTube のページを読むだけで、**ログイン状態も送りません。**
  設定と辞書と投稿履歴はブラウザ内 (`chrome.storage`) にだけ保存されます。
- **あなたがログインしているアカウントの名義でチャットに投稿します。** これが一番の注意点です。

> **本番の配信では使わないでください。** 必ず**自分の限定公開(または非公開)のテスト配信**で
> 試してください。投稿は実際にチャットへ流れます。

何をしているか気になったら、ソースは全部
[GitHub](https://github.com/max-enterme/shoutlink) にあります
(`src/` が実体、`public/manifest.json` が権限の宣言)。

## 2. 用意するもの

- Google Chrome(または Edge 等の Chromium 系)
- **自分のチャンネルのテスト配信**(限定公開でよい)。ライブチャットが開けて、
  自分でメッセージを固定できる状態
- 所要 15 分程度

---

## 3. インストール

1. 渡された ZIP を適当な場所に**展開**する(展開せずに読み込むことはできません)
2. Chrome で `chrome://extensions` を開く
3. 右上の **「デベロッパー モード」** を ON にする
4. 左上の **「パッケージ化されていない拡張機能を読み込む」** をクリック
5. 展開してできた **`manifest.json` が入っているフォルダ**を選ぶ
6. カードが出れば完了

> 詳しい手順は [install.md](install.md) にもあります。

> Chrome が「デベロッパー モードの拡張機能を無効にする」という警告を毎回出すことがあります。
> 未署名の拡張なので正常です。「キャンセル」で閉じてください。

---

## 4. 設定を開く

`chrome://extensions` の「返礼リンク」のカード → **「詳細」** → **「拡張機能のオプション」**
(別タブで開きます)。

**最初はこの状態にしてください:**

| 項目 | 最初の値 |
|---|---|
| リダイレクトを自動検知して投稿する | **ON** |
| 投稿文テンプレート | そのまま(既定) |
| コメントに反応して投稿する | **OFF のまま**(既定 OFF)← テスト H をやる場合だけ ON にします |
| 固定モード | **`off`(固定しない)** ← まず投稿だけ確認する |
| ライブチャットの右下に「↩ 返礼」を出す | **ON** ← テストのほとんどがこのボタンを使います(既定は OFF) |
| 診断ログ | **ON** ← 何が起きたかコンソールに出ます |

> 「↩ 返礼」の既定が OFF なのは、チャット窓を配信画面に載せている人に常時映り込むためです。
> テスト中は ON にしてください(切り替えにページの再読み込みは要りません)。

> **この拡張は `studio.youtube.com` のライブ管制室のチャットでしか動きません。**
> `www.youtube.com` のライブチャットは他人の配信でも開けてしまい、自分の配信かどうかを
> 判別できないためです。ポップアウトを使う場合も Studio 側のものを使ってください。

## 5. テスト

テスト配信を開始し、**YouTube Studio のライブ管制室**を開いてください
(`studio.youtube.com` → 「ライブ配信」)。**既定ではこの画面のチャットでしか動きません。**

上の設定で「↩ 返礼」を ON にしていれば、チャット部分の**右下にボタンが出ます**。
出ていれば拡張が読み込めています。**出ていない場合はここで止めて、その旨を報告してください**
(設定を ON にしたか、この画面が `studio.youtube.com` かを先に確認してください)。

> `www.youtube.com` の watch ページやポップアウトでは、既定では**動きません**(意図的です)。
> コンソールに `この画面では動かさない: ...` と出ます。

### テスト A — 投稿(固定モード `off`)

1. 右下の **「↩ 返礼」** をクリック
2. 「送信元チャンネル URL / @ハンドル」に、適当なチャンネルの URL を入れる
   - 例: `https://www.youtube.com/@example`(実在するチャンネルなら何でも構いません)
   - `@ハンドル` だけでも受け付けます
3. 「表示名」は空のままでよい
4. **「投稿して固定」** を押す

**確認すること:**

- [ ] チャットに「◯◯さんからリダイレクトありがとうございます! (URL)」が投稿されたか
- [ ] 文面が崩れていないか(URL が切れている、名前が変、など)

### テスト A' — 固定だけ試す(投稿しない)

「↩ 返礼」のパネルの下のほうに **「固定だけ試す」** があります。**投稿せず**、チャットの
**最後のメッセージ**を固定するだけの切り分け用ボタンです(設定に関わらず上書きで固定します)。

1. チャットに何か 1 行、手で書き込む
2. 「固定だけ試す」を押す

- [ ] そのメッセージが固定されたか
- [ ] パネルに `固定結果: pinned` と出たか

`unavailable` と出たら、**その環境ではメニューから固定できていない**ということです。
コンソールの `メニューに「固定」項目が見つからない` の行を展開して送ってください。

### テスト B — 実際にリダイレクトを受けられる場合のみ

他のチャンネルから実際にライブリダイレクトを受けられる環境がある人だけ。
(送る側には登録者 1,000 人以上の要件があります。受け取り許可の既定は「登録しているチャンネル」なので、
送り手のチャンネルを登録しておく必要があります。)

- [ ] リダイレクトを受けたとき、**手を触れずに**投稿・固定されたか
- [ ] 受けてから投稿まで 10 秒以内だったか
- [ ] 投稿文の **URL をクリックして、送信元チャンネルへ実際に飛ぶか**
- [ ] 動かなかった場合 → 診断ログを ON にした状態のコンソールをそのまま送ってください

> 開発者の環境では、通知の文言は `@ハンドル とその視聴者が参加しました。挨拶しましょう。` でした。
> **文言が違っていたら検知できません。**その場合は通知の文面をそのまま教えてください。

続けて、**投稿された後に**リロードでの再投稿が起きないかを確認してください
(2026-08-06 に一度壊れたことがある箇所です)。

1. 上の手順で投稿された後、**チャットのタブをポップアウトし直す**(またはページを再読み込みする)
2. 通知そのものはチャットに残り続けます。読み込み直しで拡張が同じ通知をもう一度拾うはずです

- [ ] **2 回目の投稿が出ない**か(投稿履歴に基づいて、同じ配信・同じ相手への投稿は 1 回で止まります)

### テスト C — 固定(固定モード `ifEmpty`)

1. オプションで**固定モードを `ifEmpty`** に変えて保存
2. **何も固定されていない状態**にする(固定中のメッセージがあれば解除しておく)
3. 「↩ 返礼」からもう一度実行する

- [ ] 投稿されたメッセージが**チャット上部に固定された**か

続けて、**固定されている状態のまま**もう一度実行する:

- [ ] 投稿はされるが、**さっきの固定はそのまま残っている**か(上書きされないのが正しい)

### テスト D — 固定(固定モード `always`)

1. 固定モードを **`always`** に変えて保存
2. 何かが固定されている状態で実行する

- [ ] 投稿されたメッセージが**既存の固定を上書きして**固定されたか

> `always` は既存の固定(告知など)を消します。テスト配信なので問題ないはずですが、念のため。

### テスト E — 自動だけ止められるか

**このスイッチは自動投稿だけを止めます。手動の「↩ 返礼」は意図的に通します**
(人が押した時点で意思表示なので)。ここが逆になっていないかの確認です。

1. オプションで **「リダイレクトを自動検知して投稿する」を OFF** にして保存
2. 「↩ 返礼」から実行する

- [ ] **投稿される**か(OFF でも手動からは実行できるのが正しい挙動です)
- [ ] コンソールに `自動検知が無効化されているためスキップ` が **出ない**か

実際にリダイレクトを受けられる環境なら、この状態で受けたときに
**自動では投稿されない**ことも確認できると助かります。

### テスト F — 履歴とテスト送信

**秒数で抑止する設定は無くなりました。**抑止の規則は
**「同じ配信で同じ相手には 1 回」**だけです。秒数は見ません。
**手動の「↩ 返礼」はこの抑止の対象外です**(人が押した時点で意思表示のため、
同じ相手でも押せば毎回投稿します)。

1. 「リダイレクトを自動検知して投稿する」を ON に戻す
2. 「↩ 返礼」から**同じ URL** で 2 回続けて実行する

- [ ] **2 回とも投稿される**か(手動は抑止を受けないのが正しい仕様です)
- [ ] 設定ページの **「投稿履歴」** に、投稿した相手・文面・時刻が **2 件とも**残っているか

3. 設定ページで **「履歴を消す」** を押す

- [ ] チャットのタブを**再読み込みしなくても**、投稿履歴の一覧が空になるか

4. 設定ページの辞書で、その相手の行を **`▸`** で開き、**「返礼文をテスト送信」** を押す

- [ ] 開いているライブチャットのタブへ**実際に投稿される**か
- [ ] 押した行にその場で結果(投稿した文面・投稿先の配信)が出るか
- [ ] 続けてもう一度押しても投稿できるか(**テスト送信は投稿履歴を消費しないので、
      何度でも試せます**)
- [ ] その行で「コメントに反応する」を ON にしていれば、**「コメント返しをテスト送信」**も
      同じように試せるか

> ⚠️ **呼び名を登録していない相手は、テスト送信の文面に `@ハンドル` が入ります。**
> 本番の自動検知では YouTube 上の表示名が入るため、呼び名を登録していない相手だと
> テスト送信の文面と本番の文面が一致しません。**これは不具合ではなく仕様です。**
> 呼び名を登録しておけば一致します。

### テスト G — 呼び名の辞書

設定ページの **「呼び名の辞書」**。`{name}` に入る呼び名を、チャンネルごとに登録できます。

1. **＋** の行に `@example`(実在する適当なチャンネルの @ハンドル)と呼び名を入れて ＋ を押す
2. 「↩ 返礼」から**その同じチャンネル**で実行する

- [ ] 投稿文の名前が**登録した呼び名**になったか
- [ ] 登録していないチャンネルで実行すると、**ハンドルのまま**投稿されるか
- [ ] 実行した相手が一覧に**自動で追加**されるか(呼び名は空のまま)

### テスト G' — 自由文 (`{msg}`)

同じ表の行の**左端の `▸` を押すと開きます。**開いた中に
**「自由文 (`{msg}`)」(リダイレクト返礼用)**・**コメント返し用の自由文**・
**「コメントに反応する」** の 3 つがあります。ここで見るのは 1 つ目です
(**相手ごとに違う一言**を登録して、投稿文へ差し込めます)。

> 表を畳んであるのは、1 行が持つ編集項目が 6 つに増えたためです。
> **畳んだ状態でも、設定したのに効かない行には ⚠ が出ます**(アイコンにカーソルを合わせると理由が出ます)。

> ⚠️ 冒頭にも書いたとおり、**送信元の検知は推測を含みます。取り違えると、その人に宛てて
> 書いた一文がそのまま別の相手への投稿に載ります。** テストでも、**別の人に読まれても
> 困らない内容**だけを入れてください。

1. テスト G で登録した行を **`▸`** で開き、**「自由文」** 欄に一言を入れて、**欄の外をクリック**する
   (行の編集は即保存です。下に「◯◯ の自由文を保存した」と出ます)
2. **投稿文テンプレート**を `{name}さん {msg} ありがとうございます! {url}` に変えて **保存**
3. 「↩ 返礼」から**その同じチャンネル**で実行する

- [ ] 投稿文に**登録した自由文**が入ったか
- [ ] **自由文を登録していない**チャンネルで実行すると、`{msg}` の部分が**丸ごと消え、
      余分な空白が残らない**か(`◯◯さん ありがとうございます! https://…` になる)

続けて、表示まわりを見てください。

4. テンプレートから `{msg}` を**消す**(保存はしなくてよい)

- [ ] テンプレート欄の**すぐ下**に「自由文を N 件登録していますが、テンプレートに `{msg}` が
      ありません」という警告が、**保存を待たずに**出たか
- [ ] `{msg}` を書き戻すと、**その場で消える**か

5. 自由文の欄に長い文を入れていく

- [ ] 欄の下の **「残り N 字」** が、打つたびに減るか
- [ ] **テンプレートを長くすると、この数字も一緒に減る**か(残りは**投稿文全体**の 200 字に
      対する残りで、自由文の 200 字に対する残りではありません)
- [ ] **残りが 0 を下回ると** **`◯◯ 字超過`** と赤く出るか。**この状態でも保存はできます**
      (投稿するときに 自由文 → 表示名 → 末尾 の順で削られます)
      ※ 出るのは**投稿文全体**が 200 字を超えたときです。テンプレートの定型部分・呼び名・URL が
      先に場所を食うので、**自由文が 200 字に届くよりかなり手前で出ます**(何字で出るかは
      相手の URL と呼び名の長さで変わります)。それで正常です

6. 自由文だけで **200 字を超える**文を入れて、欄の外をクリックする

- [ ] **保存されず**、「自由文は 200 字までです(今 ◯◯ 字)。保存していません」と理由が出るか
      (勝手に切り詰められて保存されていたら**それは不具合です**)

### テスト H — コメント返し(**別のアカウントが用意できる場合のみ / 任意**)

**この機能は実配信で一度も通し確認されていません。**ここが一番知りたいところです。

⚠️ **必ず自分の限定公開(または非公開)のテスト配信で。**投稿は実際にチャットへ流れます。
⚠️ **自分(配信者)自身のコメントには反応しません。**別のアカウント(サブアカウント等)から
コメントする必要があります。**そのアカウントのチャンネル URL がチャットに投稿されます**ので、
自分のものか、投稿してよいものだけを使ってください。

1. 設定の **「コメントに反応して投稿する」を ON** にして保存
2. 辞書の **＋** の行に、**コメントする側のチャンネル**の `@ハンドル` を入れて登録する
3. その行を **`▸`** で開き、**「コメントに反応する」を ON** にする
   - ON にすると、**そのチャンネルのページを 1 回だけ見に行って照合用の ID を控えます**
     (行を開いたところに `チャンネル ID: UC…` と出れば成功です)
4. テスト配信のライブチャットに、**そのアカウントで**「こんばんは」などと書き込む

- [ ] 数秒以内に、コメント返しの文面が投稿されたか(**所要時間もだいたいで教えてください**)
- [ ] **固定されていない**か(コメント返しは固定しない仕様です。されていたら不具合です)
- [ ] 同じアカウントで**もう一度コメント**しても、**2 回目は投稿されない**か
- [ ] **登録していない別のアカウント**がコメントしても、**何も起きない**か
- [ ] 拡張の投稿を引き金に、**投稿が繰り返されていない**か(**ここが一番危険な壊れ方です。
      連続していたらすぐ「コメントに反応して投稿する」を OFF にして報告してください**)
- [ ] チャットを**ポップアウトし直す / 再読み込みする**と、**過去のコメントに一斉投稿しない**か
- [ ] 自分が手でチャット入力欄に打っている最中に発火したとき、**打ちかけの文字がどうなったか**

> 行に **⚠** が出て「チャンネル ID が未解決です」となる場合、その人のコメントには反応しません。
> 辞書の上の **「未解決の行をまとめて再試行」** を押しても直らないときは、
> 行に出ている理由をそのまま送ってください。

## 6. ログの見方

拡張のログはブラウザの開発者ツールに出ます。

1. **ポップアウトしたチャットのウィンドウ**をクリックして選び、**F12** を押す
2. 「Console」タブを開く
3. `[shoutlink]` で始まる行が拡張のログです

正常な流れだとこう出ます:

```
[shoutlink] 起動した {build: ..., scope: 'Studio のライブ管制室(自分の配信)', enabled: true, ...}
[shoutlink] 投稿する (manual): ◯◯さんからリダイレクトありがとうございます! https://...
[shoutlink] 固定結果: pinned
```

`固定結果` の意味:

| 値 | 意味 |
|---|---|
| `pinned` | 固定した |
| `skipped` | 意図的に固定しなかった(`off`、または `ifEmpty` で既に固定があった) |
| `unavailable` | 固定しようとしたが**画面上の「固定」が見つからなかった** ← 報告してほしい |

テスト H(コメント返し)では、代わりにこの形で出ます:

```
[shoutlink] コメント返しの対象を検知した: https://www.youtube.com/@...
[shoutlink] コメント返しを投稿する: ◯◯さん、来てくれてありがとうございます! https://...
```

投稿されなかったときは、**理由つきの行が 1 本出ます。2 種類あります。**

- **`コメント返しをしない (理由)`** … コメントを見た時点で対象外と判断したとき。
  理由は `辞書に該当が無い` / `コメントに反応しない設定` / `配信者自身のコメント` /
  `この配信では投稿済み` / `自分の投稿と本文が一致` / `コメント返しが無効` のいずれかです。
  **普通の視聴者のコメントは全部 `辞書に該当が無い` になります**(正常です)
- **`コメント返しを見送った (理由)`** … 投稿する直前まで進んでからやめたとき。
  `limit`(**1 配信 20 件の上限**)/ `discarded`(スイッチを OFF にしたので捨てた)や、
  **順番待ちの間に状況が変わった**場合(先に別の返礼が入って `この配信では投稿済み` になった等)です

**どちらの行もそのまま切り分けの材料になるので、コピーして送ってください。**

## 7. 動かないときに送ってほしいもの

### (a) コンソールのログ

Console タブで右クリック →「Save as...」で保存するか、`[shoutlink]` の行をコピーして貼ってください。

### (b) 画面構造(DOM)— これが一番助かります

ライブチャットのウィンドウの Console に、以下を**1 行ずつ貼って実行**し、結果を送ってください。

**① ライブチャットで使われている部品の一覧:**

```js
[...new Set([...document.querySelectorAll('*')].map(e => e.tagName.toLowerCase()))].filter(t => t.startsWith('yt-live-chat'))
```

**② 「固定中」のバナーの構造(何かを固定した状態で実行):**

```js
[...document.querySelectorAll('*')].filter(e => /pinned|banner/i.test(e.tagName)).map(e => [e.tagName.toLowerCase(), e.id, e.textContent.trim().slice(0, 40)])
```

**③ メッセージのメニュー項目(自分のメッセージの ⋮ を手で開いた状態で実行):**

```js
[...document.querySelectorAll('[role="menuitem"], ytd-menu-service-item-renderer')].map(e => [e.tagName.toLowerCase(), e.textContent.trim()])
```

**④ リダイレクトを受けた場合のみ — 通知が出た直後に実行(クリップボードにコピーされます):**

```js
copy(document.querySelector('yt-live-chat-item-list-renderer')?.outerHTML)
```

> ⚠️ **④ の結果には、チャットにいる視聴者の名前や ID がそのまま入っています。**
> 送る前に、**チャンネル名・ハンドル・ID を適当な文字列に置き換えてください**
> (リダイレクトの送信元だけ分かれば十分です)。判断に迷ったら、置換せずに送るのではなく
> 先に相談してください。
