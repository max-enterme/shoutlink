### 詳細な説明 (Detailed description) — **これを貼る**

```
YouTube のライブ配信で他チャンネルからのライブリダイレクトやコメントを受け取ったとき、
送信元チャンネルの URL をライブチャットへ投稿したり固定したりする Chrome 拡張です。

配信中に「誰が来てくれたのか」を確認して、チャンネル URL をコピーして、投稿して、
必要なら固定する。この一連の操作を肩代わりします。

■ 引き金は 2 種類あります

1. ライブリダイレクトの受信 … 検知 → 投稿 → 固定
2. 登録した人のコメント     … 検知 → 投稿 (固定はしません)

2 は「コメント返し」で、設定のスイッチと辞書の行ごとのフラグの
両方を自分で ON にしない限り動きません (どちらも既定 OFF)。
投稿が増えすぎないよう、同じ配信・同じ人には 1 回まで / 投稿の間隔は最低 5 秒、
を設定では変えられない固定値にしています。

■ 投稿文

テンプレートで編集できます。{name} に呼び名 (未設定ならハンドルか検知した表示名)、
{url} にチャンネル URL、{msg} に相手ごとの自由文が入ります。
リダイレクト返礼とコメント返しで、テンプレートも自由文も別に持ちます。

■ 動く条件

・Chrome (確認しているのは Chrome だけです)
・YouTube Studio のライブ管制室のチャット (studio.youtube.com/live_chat)
  www.youtube.com のライブチャットでは動きません。他人の配信でも開けてしまい、
  自分の配信かどうかを判別できないためです (意図的です)
・YouTube Studio の表示言語が日本語であること
  検知はリダイレクト通知の文言に依存しているため、他言語では反応しません

■ 保存と通信

設定・呼び名の辞書・投稿履歴は、すべてブラウザの中に保存されます。

設定ページで「コメントに反応する」を ON にしたときに、
辞書に登録されているチャンネルのページを 1 回だけ取得して、照合用のチャンネル ID を
控えます。ライブチャットの画面からは通信しません。

  プライバシーポリシー:
  https://github.com/max-enterme/shoutlink/blob/main/docs/privacy-policy.md

■ 入れる前に知っておいてください

・投稿はあなたのアカウントの名義で、あなたのチャンネルの発言として残ります。

・送信元の検知は画面の表示からの推測です。取り違えると、その人に宛てて書いた
  自由文 ({msg}) がそのまま別の相手への投稿に載ります。
  取り違えて別の人に読まれても困らない内容だけを書いてください。

・YouTube の画面構造に依存しているため、構造が変わると動かなくなることがあります。
  そのときは反応しなくなるだけで、誤って投稿する形では壊れません。

・動作を確認できているのは日本語 UI・Studio のチャット・1 環境だけです。
  想定どおりに動かないことがあります。

自己責任でお使いください。

  設定のしかた、動かないときの切り分け、どこまで確認できているかの詳細:
  https://max-enterme.github.io/shoutlink/
```

### 掲載文に必ず残すもの (削らない)

**基準は「読むと行動が変わるか」。**行動が変わらないものは、正しくても載せない。

  (プライバシーポリシーと Privacy タブの申告が担当)

1. **自分のアカウント名義で、自分のチャンネルの発言として残る**こと
2. **送信元の検知は推測なので取り違えうる** → 自由文には**取り違えても困らない内容だけ**書く

## 2. Privacy タブ

### 単一用途 (Single purpose) — **これを貼る**

```
配信者が自分のライブ配信で受け取ったライブリダイレクト、または自分が辞書に登録した
相手のコメントを検知して、その相手のチャンネル URL を自分のライブチャットへ投稿する。
```

> **引き金は 2 つだが、やることは 1 つ (相手の URL を投稿する)。**
> 2 機能と見なされる可能性があるので、説明はこの形で通す。
> リダイレクト受信もコメントも「来てくれた相手を見つける」手段であって、
> **拡張がやることはどちらも「その相手のチャンネル URL を投稿する」一つだけ**、と書く。
> それでも通らなかったときの分岐は rail #447 の detail にある。

### 権限の正当化 — **これを貼る**

⚠️ **入力欄は 2 つしかない。**「storage が必要な理由」と「**ホスト権限 が必要な理由**」。
**ホストごとに分かれていない**ので、`studio.youtube.com` と `www.youtube.com` を
**1 つの欄にまとめて書く**(実物で確認 / 2026-08-23)。各欄 **1,000 字**まで。

**`storage が必要な理由`**

```
設定 (自動検知の有無、投稿文テンプレート、固定モードなど)、
呼び名の辞書 (相手ごとの呼び名・自由文・チャンネル ID)、投稿履歴を、
利用者のブラウザ内に保存するために使用します。
投稿履歴はチャットを開き直したときの再投稿を防ぐために必要です。
保存先は chrome.storage で、外部へ送信することはありません。
```

**`ホスト権限 が必要な理由`**

```
2 つのホスト権限を使っており、役割が異なります。

studio.youtube.com — コンテンツスクリプトの注入先です。ライブ管制室のライブチャット
(studio.youtube.com/live_chat) で、リダイレクトの受信通知とコメントの検知、
チャットへの投稿、投稿の固定を行います。本拡張が動作するのはここだけです。

www.youtube.com — 設定ページから、利用者が辞書に登録したチャンネルのページを
1 回だけ取得して、コメントの投稿者を照合するためのチャンネル ID (UC...) を
読み取るために使用します。取得はログイン状態を送らずに行います
(credentials: 'omit')。このホストにコンテンツスクリプトは注入せず、
ライブチャットの画面からは通信しません。
```

> ⚠️ **`www.youtube.com` が広すぎるという指摘は想定内。**用途は設定ページからの 1 回の GET だけで、
> **content script の対象は `studio.youtube.com/live_chat*` のまま**であることを説明する
> (`tests/manifest.test.ts` が機械で固定している / [security-review.md](security-review.md) S10)。

> **ホスト権限があると審査が長くなる。**フォームに
> 「ホスト権限が要求されているため、詳しい審査が必要となり、公開が遅れる可能性があります」
> という警告が出る(実物で確認)。**想定内。**避ける手段は無い。

### リモートコード

**ラジオボタンで「いいえ、リモートコードを使用していません」を選ぶ。**

⚠️ **初期状態が「はい、リモートコードを使用しています」になっていることがある**(2026-08-23 に遭遇)。
**はいのままだと事実と食い違う申告になる。**必ず「いいえ」に変えること。
「はい」を選ぶと理由の入力欄が出るが、**こちらは使わない。**

フォームの説明にはこうある(実物):
「リモートコードは、拡張機能のパッケージに含まれていない JS または Wasm です。
`<script>` タグ内の外部ファイルへの参照、外部ファイルを指すモジュール、
`eval()` による文字列の検証などもこれに該当します」
→ **`package:store` が機械で見ている項目とほぼ同じ。**

`npm run package:store` が提出物を作るたびに機械で確認している —
`eval()` / `new Function()` / `importScripts()` / 動的 `import()` / HTML の外部 `src`・`href`
のいずれかがあれば ZIP を作らずに止まる
(→ [setup-and-verify.md](setup-and-verify.md) の「ストア提出用の ZIP を作る」)。

⚠️ **設定ページの `www.youtube.com` への GET は、取得した HTML を読むだけで
コードとして実行しない。**リモートコードには当たらない。

### データの取り扱い

**外部へ送信するものは無い。** 正本は [privacy-policy.md](privacy-policy.md)。

- 開発者のサーバが存在しない。解析・広告 SDK も無い。
- 設定・辞書・投稿履歴は `chrome.storage` (`sync` / `local`) に置くだけ。
- 通信は 1 か所だけ — 設定ページ → `www.youtube.com` のチャンネルページを
  `credentials: 'omit'` で GET。**利用者のデータは何も送らない。**

### 収集データのカテゴリ — **2026-08-23 に確定**

> ⚠️ **以前ここに「判断の基準は端末の外へ出るか。本拡張は何も出さないので該当は無いはず」と
> 書いていたが、これは誤りだった。**
> [User Data FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq):
> 「Extensions are required to disclose how they handle user data, **even when data is processed
> or stored locally on a user's device and is not transmitted** to external servers or third parties.」
> **ローカル処理でも申告対象。**さらに Google の user data の定義には
> **"Website content and resources"** が明記されている。

**チェックする 2 つ:**

| 項目 | なぜ |
|---|---|
| **ウェブサイトのコンテンツ** | ライブチャットの DOM(通知の文言・コメント本文・チャンネル URL)を読む。定義に "Website content and resources" が明記されている。**議論の余地なし** |
| **個人を特定できる情報** | 辞書に**チャンネル ID (`UC…`) = アカウント識別子**と、利用者が付けた**呼び名(実名でありうる)**を保存する。定義は "username" と "any type of identification number, such as … account number" を含む |

**チェックしない 7 つ** — 健康 / 財務状況や支払い / 認証 / **個人的コミュニケーション** /
位置情報 / ウェブ履歴 / ユーザーのアクティビティ。
認証は `credentials: 'omit'` で**意図的に送らない。**

> **個人的コミュニケーションを外した理由**(迷った項目なので残す):
> 自己エコー抑止でコメント本文を読むが、**公開のライブチャット**であって「メール・DM」的な私信ではない。
> 読んだ本文は保存もしない。**「ウェブサイトのコンテンツ」で覆われる。**

**倒し方の原則:** 迷ったら**チェックする側**へ倒す。
**過少申告はポリシー違反**(審査・掲載取り下げのリスク)だが、**過剰申告は「実際より多く扱うように
見える」だけ**で、その誤解は詳細な説明文と [privacy-policy.md](privacy-policy.md) が打ち消す。

### 証明のチェック 3 つ — **すべて入れる**(文言は実物のまま)

```
私は、承認されている以外の用途で第三者にユーザーデータを販売、転送しません
私はアイテムの唯一の目的と関係のない目的でユーザーデータを使用または転送しません
私は信用力を判断する目的または融資目的でユーザーデータを使用または転送しません
```

**3 つとも該当する。**販売も転送もせず(送信先が無い)、単一用途以外に使わず、信用調査にも使わない。

### プライバシーポリシーの URL — **確認済み。blob URL を使う**

```
https://github.com/max-enterme/shoutlink/blob/main/docs/privacy-policy.md
```

**GitHub Pages の URL は使えない。**
`https://max-enterme.github.io/shoutlink/privacy-policy.md` は
**`Content-Type: text/markdown` で配信される**ため (`docs/.nojekyll` があり md → HTML の変換をしない)、
ブラウザで開くと**表示ではなくダウンロードになる。**審査で読まれる URL としては使えない。

**blob URL なら github.com が markdown を描画する。**HTML を別に用意して二重管理にするより、
正本 1 つを指すほうが食い違わない。

## 4. Account タブ — 登録時に決めるもの

**デベロッパー登録の時点で決まり、あとから戻しにくい**もの。掲載の中身より先に来る。

### トレーダー申告 — **非トレーダー** (2026-08-23 / 人間)

**結論: 非トレーダーで申告する。**

これは Google の区分ではなく **EU のデジタルサービス法 (DSA) の消費者保護の枠組み**で、
狙いは「商売として物を出している相手なら、消費者が誰に連絡すればよいか分かるようにする」こと
([Trader FAQ](https://developer.chrome.com/docs/webstore/program-policies/trader-verification-faq))。
Google が引く**非トレーダー**の定義:

> 自分の取引・事業・技能・職業の**外側**の目的で行動する自然人または法人 —
> **このマーケットプレイス上の契約に関して**

**軸は「ストア上で契約 (取引) が発生するか」**であって、本人が職業を持っているかではない。

**当てはめ:**

| | |
|---|---|
| 有償・課金・サブスク | **無い** |
| 広告 | **無い** |
| 解析・データ収集 | **無い**(開発者のサーバすら存在しない → [privacy-policy.md](privacy-policy.md)) |
| 自社サービスへの導線 | **無い** |
| 公開範囲 | **限定公開。検索にも出ない** |

→ **ストア上で「契約」に当たるものが何も起きない。**

**唯一の引っかかり:** max は配信者で、それは職業に当たりうる。拡張も max 名義で出る。
「配信という職業に関わる目的」と読む余地はゼロではない。
ただし定義が「**このマーケットプレイス上の契約に関して**」と限定しているため、
**ストアで何も売っていない以上、当てはめにくい**というのが素直な読み。

**⚠️ トレーダーと申告すると、法的な氏名・住所・電話番号が掲載ページの下部に公開される**
(DSA の要求で電話番号は必須)。**これは公開側 ↔ private の境界を破る。**
非トレーダーなら公開されるものは無い。
**外したときの損害が釣り合っていない** — 片方は本名と住所が出る、もう片方は指摘されたら直す。

**⚠️ この判断は「お金が絡まない」ことに依存している。**
**有償になる / 広告が入る / 有料サービスへの導線になる**のどれかが起きたら、**申告を見直す。**

> **判断は本人が行った。** Google は FAQ で「各パブリッシャーが自分で判断すること。
> 個別の回答はできない」と明言しており、**Google からも作者からも「正解」は示されない。**
> Google が異議を唱えたときの対応は**一次情報で確認できなかった**(FAQ に記載なし)。
