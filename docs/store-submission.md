### 詳細な説明 (Detailed description) — **これを貼る**

```
YouTube のライブ配信で他チャンネルからライブリダイレクトを受け取ったとき、
送信元チャンネルの URL をライブチャットへ投稿して固定する Chrome 拡張です。

配信中に「誰から来たのか」を確認して、チャンネル URL をコピーして、投稿して、固定する。
この一連の操作を、リダイレクトを受け取った時点で肩代わりします。

■ 引き金は 2 種類あります

1. ライブリダイレクトの受信 … 検知 → 投稿 → 固定
2. 登録した人のコメント     … 検知 → 投稿 (固定はしません)

2 は「コメント返し」で、設定のスイッチと辞書の行ごとのフラグの
両方を自分で ON にしない限り動きません (どちらも既定 OFF)。
ON にすると投稿の頻度は上がります。コメントはリダイレクトより桁違いに多いためです。
歯止めとして、同じ配信・同じ人には 1 回まで / 投稿の間隔は最低 5 秒 /
1 配信あたり 20 件まで、を設定では変えられない固定値にしています。

■ 投稿文

テンプレートで編集できます。{name} に呼び名 (未設定ならハンドルか検知した表示名)、
{url} にチャンネル URL、{msg} に相手ごとの自由文が入ります。
リダイレクト返礼とコメント返しで、テンプレートも自由文も別に持ちます。

■ 動く条件

・Chrome (確認しているのは Chrome だけです)
・YouTube Studio のライブ管制室のチャット (studio.youtube.com/live_chat)
  www.youtube.com のライブチャットでは動きません。他人の配信でも開けてしまい、
  自分の配信かどうかを判別できないためです (意図的です)
・YouTube Studio の表示言語が日本語であること
  検知はリダイレクト通知の文言に依存しているため、他言語では反応しません

■ 保存されるもの

開発者のサーバへ送るものはありません (開発者のサーバ自体がありません)。
解析も広告もありません。設定・呼び名の辞書・投稿履歴は、すべてブラウザの中に保存されます。

通信するのは 1 か所だけです。設定ページで「コメントに反応する」を ON にしたときに、
辞書に登録されているチャンネルのページを 1 回だけ取得して、照合用のチャンネル ID を
控えます (ログイン状態は送りません)。ライブチャットの画面からは通信しません。

  プライバシーポリシー:
  https://github.com/max-enterme/yt-redirect-pin/blob/main/docs/privacy-policy.md

■ 入れる前に必ず読んでください
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ストアの審査は、単一用途・権限・データの扱いを見るものです。
YouTube の規約に触れるかどうかは見てくれません。
審査を通ったことは「規約上セーフ」の裏付けにはなりません。

・YouTube の規約上、グレーな行為を含みます。
  利用規約は「自動化された手段を使用して本サービスにアクセスすること」を
  禁じています。本拡張がこれに当たるかは文言からは決まらず、YouTube の公式見解も、
  この形での処分の前例も見つかっていません。
  「安全である証拠」ではなく「証拠が無い」という状態です。

・投稿はあなた自身のアカウントの名義で行われます。
  何かあったとき失うのは、開発者ではなくあなたのチャンネルです。

・送信元の検知は推測を含みます。取り違えると、その人に宛てて書いた一文 ({msg}) が
  そのまま別の相手への投稿に載ります。実際にこの拡張は送信元の取り違えを
  過去に 2 回起こしています。取り違えて別の人に読まれても困らない内容だけを
  書いてください。

・ほとんど検証されていません。実配信で通ったのは日本語 UI・Studio のチャット・
  1 環境だけです。既定の固定モードの判定、自由文入りの文面、コメント返しは、
  いずれも実配信での通し確認が未実施です。

・YouTube の画面構造が変われば、ある日突然動かなくなります (DOM に依存しているため)。
  直すまで反応しなくなるだけで、誤って投稿する形では壊れません。

リスクを自分で判断・管理できる人が、自己責任で使うことを想定しています。
判断がつかない場合は、使わないでください。作者は結果について責任を負いません (MIT / 無保証)。

  何をどこまで確かめたか、何がグレーなのかは全部ここに書いてあります:
  https://max-enterme.github.io/yt-redirect-pin/
```

## 2. Privacy タブ

### 単一用途 (Single purpose) — **これを貼る**

```
配信者が自分のライブ配信で受け取ったライブリダイレクト、または自分が辞書に登録した
相手のコメントを検知して、その相手のチャンネル URL を自分のライブチャットへ投稿する。
```

> **引き金は 2 つだが、やることは 1 つ (相手の URL を投稿する)。**
> 2 機能と見なされる可能性があるので、説明はこの形で通す。
> リダイレクト受信もコメントも「来てくれた相手を見つける」手段であって、
> **拡張がやることはどちらも「その相手のチャンネル URL を投稿する」一つだけ**、と書く。
> それでも通らなかったときの分岐は rail #447 の detail にある。

### 権限の正当化 — **これを貼る**

**`storage`**

```
設定 (自動検知の有無、投稿文テンプレート、固定モード、クールダウン秒数など)、
呼び名の辞書 (相手ごとの呼び名・自由文・チャンネル ID)、投稿履歴を、
利用者のブラウザ内に保存するために使用します。
投稿履歴はチャットを開き直したときの再投稿を防ぐために必要です。
保存先は chrome.storage で、外部へ送信することはありません。
```

**`https://studio.youtube.com/*` (host permission)**

```
コンテンツスクリプトの注入先です。ライブ管制室のライブチャット
(studio.youtube.com/live_chat) で、リダイレクトの受信通知とコメントの検知、
チャットへの投稿、投稿の固定を行います。本拡張が動作するのはここだけです。
```

**`https://www.youtube.com/*` (host permission)**

```
設定ページから、利用者が辞書に登録したチャンネルのページを 1 回だけ取得して、
コメントの投稿者を照合するためのチャンネル ID (UC...) を読み取るために使用します。
取得はログイン状態を送らずに行います (credentials: 'omit')。
このホストにコンテンツスクリプトは注入しません。ライブチャットの画面からは通信しません。
```

> ⚠️ **`www.youtube.com` が広すぎるという指摘は想定内。**用途は設定ページからの 1 回の GET だけで、
> **content script の対象は `studio.youtube.com/live_chat*` のまま**であることを説明する
> (`tests/manifest.test.ts` が機械で固定している / [security-review.md](security-review.md) S10)。

### リモートコード

**「使用していない (No, I am not using remote code)」を選ぶ。**

`npm run package:store` が提出物を作るたびに機械で確認している —
`eval()` / `new Function()` / `importScripts()` / 動的 `import()` / HTML の外部 `src`・`href`
のいずれかがあれば ZIP を作らずに止まる
(→ [setup-and-verify.md](setup-and-verify.md) の「ストア提出用の ZIP を作る」)。

⚠️ **設定ページの `www.youtube.com` への GET は、取得した HTML を読むだけで
コードとして実行しない。**リモートコードには当たらない。

### データの取り扱い

**外部へ送信するものは無い。** 正本は [privacy-policy.md](privacy-policy.md)。

- 開発者のサーバが存在しない。解析・広告 SDK も無い。
- 設定・辞書・投稿履歴は `chrome.storage` (`sync` / `local`) に置くだけ。
- 通信は 1 か所だけ — 設定ページ → `www.youtube.com` のチャンネルページを
  `credentials: 'omit'` で GET。**利用者のデータは何も送らない。**

⚠️ **収集データのカテゴリのチェックは、ダッシュボードの実物の選択肢を見て埋める。**
このページの調査では**選択肢の正確な文言を一次情報で取れなかった。**推測で埋めない。
判断の基準は「**端末の外へ出るか**」— 本拡張は何も出さないので、該当は無いはず。
**ページの内容を読む (Website content) をどう扱うかだけ、実物の説明文を読んで決める。**

**証明のチェック 3 つ** (販売しない / 単一用途と無関係な用途に使わない / 信用調査に使わない) は
**すべて該当する**ので入れる。⚠️ **文言も実物で確認する** (この調査では一次情報を取れなかった)。

### プライバシーポリシーの URL — **確認済み。blob URL を使う**

```
https://github.com/max-enterme/yt-redirect-pin/blob/main/docs/privacy-policy.md
```

**GitHub Pages の URL は使えない。**
`https://max-enterme.github.io/yt-redirect-pin/privacy-policy.md` は
**`Content-Type: text/markdown` で配信される**ため (`docs/.nojekyll` があり md → HTML の変換をしない)、
ブラウザで開くと**表示ではなくダウンロードになる。**審査で読まれる URL としては使えない。

**blob URL なら github.com が markdown を描画する。**HTML を別に用意して二重管理にするより、
正本 1 つを指すほうが食い違わない。

## 4. Account タブ — 登録時に決めるもの

**デベロッパー登録の時点で決まり、あとから戻しにくい**もの。掲載の中身より先に来る。

### トレーダー申告 — **非トレーダー** (2026-08-23 / 人間)

**結論: 非トレーダーで申告する。**

これは Google の区分ではなく **EU のデジタルサービス法 (DSA) の消費者保護の枠組み**で、
狙いは「商売として物を出している相手なら、消費者が誰に連絡すればよいか分かるようにする」こと
([Trader FAQ](https://developer.chrome.com/docs/webstore/program-policies/trader-verification-faq))。
Google が引く**非トレーダー**の定義:

> 自分の取引・事業・技能・職業の**外側**の目的で行動する自然人または法人 —
> **このマーケットプレイス上の契約に関して**

**軸は「ストア上で契約 (取引) が発生するか」**であって、本人が職業を持っているかではない。

**当てはめ:**

| | |
|---|---|
| 有償・課金・サブスク | **無い** |
| 広告 | **無い** |
| 解析・データ収集 | **無い**(開発者のサーバすら存在しない → [privacy-policy.md](privacy-policy.md)) |
| 自社サービスへの導線 | **無い** |
| 公開範囲 | **限定公開。検索にも出ない** |

→ **ストア上で「契約」に当たるものが何も起きない。**

**唯一の引っかかり:** max は配信者で、それは職業に当たりうる。拡張も max 名義で出る。
「配信という職業に関わる目的」と読む余地はゼロではない。
ただし定義が「**このマーケットプレイス上の契約に関して**」と限定しているため、
**ストアで何も売っていない以上、当てはめにくい**というのが素直な読み。

**⚠️ トレーダーと申告すると、法的な氏名・住所・電話番号が掲載ページの下部に公開される**
(DSA の要求で電話番号は必須)。**これは公開側 ↔ private の境界を破る。**
非トレーダーなら公開されるものは無い。
**外したときの損害が釣り合っていない** — 片方は本名と住所が出る、もう片方は指摘されたら直す。

**⚠️ この判断は「お金が絡まない」ことに依存している。**
**有償になる / 広告が入る / 有料サービスへの導線になる**のどれかが起きたら、**申告を見直す。**

> **判断は本人が行った。** Google は FAQ で「各パブリッシャーが自分で判断すること。
> 個別の回答はできない」と明言しており、**Google からも作者からも「正解」は示されない。**
> Google が異議を唱えたときの対応は**一次情報で確認できなかった**(FAQ に記載なし)。

### 登録に使う Google アカウント

**⚠️ 後から変更できない。**

> After an account is created, **you cannot change its email address.**
> ([Register](https://developer.chrome.com/docs/webstore/register))

公式は**公開専用に新しいメールアカウントを作ることを勧めている。**

### 公開表示名 (publisher display name)

**各拡張のタイトルの下に出る。** → **max 名義にする**(当人の本名を出さない)。

### 連絡先メール

**デベロッパーアカウントのメール (通知用) とは別物で、こちらは拡張の連絡先情報として掲載に出る。**
登録時に**確認メールでの検証が要る。**
**公開名義のアドレスを選ぶ**(当人の個人アドレスにしない)。
