# 導入・設定・切り分け

[README](../README.md) の **⚠️ 使う前に読んでください** を読んでから進めてください。

## 0. 前提

| | |
|---|---|
| ブラウザ | Chrome (Chromium 系なら概ね動くはずですが、確認しているのは Chrome だけです) |
| 画面 | YouTube Studio のライブ管制室のチャット (`studio.youtube.com`)。`www.youtube.com` では動きません |
| **表示言語** | **YouTube Studio が日本語であること。** 検知はリダイレクト通知の**文言**に依存しているため、他言語では反応しません |

> 「入れたのに反応しない」の一番多い原因が、この表示言語と画面の取り違えです。

## 1. 入れる

**Chrome ウェブストア (限定公開) から入れます。**

→ **<https://chromewebstore.google.com/detail/kpjfmcppkncdmehdpgcochaanbmodaim>**

1. 上の URL を Chrome で開く
2. **「Chrome に追加」** を押す
3. 許可の確認が出るので、内容を読んで **「拡張機能を追加」**
4. **「返礼リンク」** のカードが `chrome://extensions` に出れば完了

限定公開なので、**ストアの検索・カテゴリ一覧からは見つかりません。**この URL からだけ入ります。
署名されているので、**起動のたびの警告は出ず、新しい版は Chrome が自動で入れ替えます。**

> ⚠️ **デベロッパーモードで前の版を入れている人は、先に読んでください** →
> [デベロッパーモード版から入れ替える](#デベロッパーモード版から入れ替える)。
> **設定・呼び名の辞書・投稿履歴は引き継がれません。**

### 求められる許可について

入れると、拡張のカードに **`studio.youtube.com` と `www.youtube.com` のデータの読み取り・変更**が
表示されます。それぞれ役割が違います。

| ホスト | 何のためか |
|---|---|
| `studio.youtube.com` | **拡張が読み込まれて動くのはここだけです** (ライブ管制室のチャット `studio.youtube.com/live_chat*`)。検知・投稿・固定を行います |
| `www.youtube.com` | **設定画面が、辞書に登録したチャンネルのページを 1 回だけ読みに行く**ためのものです (コメントの投稿者と照合するためのチャンネル ID を控える / 下の「コメント返し」)。**このページに拡張が読み込まれることはありません。この取得を行うのは設定画面だけで、ライブチャットの画面では行いません** |

> ⚠️ **`www.youtube.com` のライブチャットで拡張が動くようになった、という意味ではありません。**
> 過去に一度、`www.youtube.com` でも拡張が動いてしまい、**他人の配信のチャットへ投稿する**という
> 事故を起こしています (2026-08-06)。**今回増えたのは「ページを取得してよい」という許可だけ**で、
> 拡張が読み込まれる範囲は `studio.youtube.com/live_chat*` のまま変わっていません
> (→ [security-review.md](security-review.md) S10)。

### デベロッパーモード版から入れ替える

**ZIP をデベロッパーモードで読み込んで使っていた人向けです。**

> ⚠️ **設定・呼び名の辞書・投稿履歴は引き継がれません。**拡張を削除すると、その拡張に
> 保存されていたものも一緒に消えます。**要るなら、消す前に書き出してください。**

**順番を守ってください。先に削除、あとからストア版です。**

1. **書き出す。** 拡張の設定ページ (`chrome-extension://<いまの ID>/options.html`) を開いて
   **F12** → Console で下を実行し、クリップボードに入った JSON をファイルへ保存する

   ```js
   Promise.all([chrome.storage.local.get(null), chrome.storage.sync.get(null)])
     .then(([local, sync]) => copy(JSON.stringify({ local, sync })))
   ```

2. `chrome://extensions` で**いまの「返礼リンク」を削除**する
3. [ストアの URL](https://chromewebstore.google.com/detail/kpjfmcppkncdmehdpgcochaanbmodaim) から入れ直す
4. **書き戻す。** ストア版の設定ページの Console で

   ```js
   const saved = /* 1 で保存した JSON を貼る */
   Promise.all([chrome.storage.local.set(saved.local), chrome.storage.sync.set(saved.sync)])
     .then(() => location.reload())
   ```

> ⚠️ **投稿履歴 (`ytRedirectPin.postLog`) も一緒に書き戻してください。**捨てると再投稿の抑止が
> 白紙になり、**同じ配信で既に返礼した相手へもう一度投稿することがあります。**
> 上の書き出しは `get(null)` で全部取っているので、貼り戻せばそのまま入ります。

> **なぜ「先に削除」なのか。** 0.2.0 以前のデベロッパーモード版は**ストア版とは別の拡張 ID** です。
> 消さないまま入れると **2 つとも動いて、同じ相手へ 2 回投稿します。**
> 0.3.0 のデベロッパーモード版は `key` を差し替えてあり**ストア版と同じ ID**なので、
> 並べて置くことはできません。どちらにしても、先に消してからストア版を入れます。

### 新しい版に入れ替える

**ストア版は自動更新です。何もしなくても、しばらくすると新しい版に入れ替わります。**

すぐ上げたいときは `chrome://extensions` で **「デベロッパー モード」** を ON にして
**「更新」** を押してください (拡張自体はストア版のままです)。版はカードで確認できます。
**設定・呼び名の辞書・投稿履歴は、更新では消えません。**

### ZIP から入れる (開発者向け)

**通常は上のストアから入れてください。**この手順が要るのは、自分でビルドした `dist/` や
[過去の Release](https://github.com/max-enterme/shoutlink/releases) の ZIP を試すときだけです。

1. ZIP を**展開する。** 展開せずに読み込むことはできません
2. 展開したフォルダを、**消さない場所に置く**
   (Chrome は起動のたびにこのフォルダを読みます。消す・移動すると拡張も消えます)
3. Chrome で `chrome://extensions` を開く
4. 右上の **「デベロッパー モード」** を ON にする
5. 左上の **「パッケージ化されていない拡張機能を読み込む」** を押す
6. **`manifest.json` が入っているフォルダ**を選ぶ

> ⚠️ **ストア版と同時には使えません。** 0.3.0 以降のビルドはストア版と同じ拡張 ID です。
> 先にストア版を削除してください (**設定・辞書・投稿履歴は消えます** → 上の書き出し手順)。

#### 未署名であることの影響

ZIP から入れた場合の話です。**ストア版には当てはまりません。**

- **Chrome が起動のたびに「デベロッパー モードの拡張機能を無効にする」と聞いてきます。**
  未署名の拡張なので正常です。「キャンセル」で閉じてください
- **自動更新されません。** 直しても、新しい版は自分で入れ替えるまで届きません

## 2. 設定する

`chrome://extensions` のカード → **「詳細」** → **「拡張機能のオプション」**

| 項目 | 意味 |
|---|---|
| リダイレクトを自動検知して投稿する | 外すと**リダイレクト返礼の自動投稿だけが止まります**。手動の「↩ 返礼」からは引き続き実行できます。**コメント返しはこのスイッチでは止まりません** (下の別スイッチ) |
| 投稿文テンプレート | `{name}` に表示名、`{url}` にチャンネル URL、`{msg}` に送信元ごとの自由文が入る。下にプレビューが出ます |
| **コメントに反応して投稿する** | **コメント返しのスイッチ。既定は OFF。**ON にすると、辞書で「コメントに反応する」を付けた人がチャットにコメントしたときに投稿します (→ 下の「コメント返し」) |
| **コメント返しの文面** | リダイレクト返礼とは**別のテンプレート**(既定 `{name}さん、来てくれてありがとうございます! {url}`)。`{msg}` に入るのも**コメント返し用の自由文**で、リダイレクト返礼用の自由文とは別のフィールドです |
| ライブチャットの右下に「↩ 返礼」を出す | 手動トリガーのパネル。**既定は OFF** — チャット窓を配信画面に載せていると常時映り込むため。切り替えにページの再読み込みは不要 |
| 固定モード | `off` … 投稿だけ / `ifEmpty` … 既存の固定が無いときだけ固定 (既定) / `always` … 上書きして固定。**コメント返しはこの設定に関わらず固定しません** |
| 多重発火の抑止 | **同じ配信で同じ相手には 1 回まで。**秒数では判定しません。判定はこの端末の投稿履歴に基づくのでリロードをまたいでも引き継がれます。配信 ID を取れない画面では**6 時間の窓**で同一配信とみなします。**リダイレクト返礼・コメント返しとも同じ規則です** |
| 投稿履歴 | 投稿できたときだけ「誰に・何を・いつ・**どちらの種別で**」をこの端末に記録します (再投稿の判定用。同期しません)。ここから消せます (消すとチャットのタブにも再読み込みなしで届きます) |
| 呼び名の辞書 | `{name}` を置き換える呼び名と、`{msg}` に入る自由文。リダイレクトを受けた相手は自動で載ります (どの欄も空のまま)。**この端末にだけ保存され、同期しません**。行の左端の **▸** を押すと、**リダイレクト返礼用の自由文 / コメント返し用の自由文 / 「コメントに反応する」 / テスト送信の 2 ボタン** が開きます (自由文はどちらも 1 件 200 字まで)。**テスト送信は開いているライブチャットのタブへ実際に投稿しますが、投稿履歴には残らないので何度でも試せます** |
| 診断ログ | **既定は OFF。**検知が動かないときの切り分け用で、ON にすると**通知の候補になりうるノードだけ**をコンソールに出します (通常のコメントは除外していますが、それを含む親ノードが引っかかると本文が混ざることがあります) |

> YouTube の固定は **1 件しか置けません。** `always` は告知などの既存の固定を消します。
> `ifEmpty` は「現在何かが固定されているか」の DOM 判定に依存していて、**これは未検証です**。

### 自動投稿を使わない設定

1. 「リダイレクトを自動検知して投稿する」を **OFF**
2. 「ライブチャットの右下に『↩ 返礼』を出す」を **ON** (既定は OFF なので、入れないとボタンが出ません)
3. 「コメントに反応して投稿する」は **OFF のまま** (**既定 OFF**。1 のスイッチでは止まりません)

**この形なら、書き込みは自分がボタンを押したときにしか起きません。**
自動検知に任せるのが不安なら、まずこの使い方から始めるのを勧めます。

---

> **設定**は `chrome.storage.sync` に保存されます (使えない環境では `local`)。
> **`sync` に載ると、Chrome の同期を有効にしている場合、同じ Google アカウントの別の PC にも複製されます。**
>
> **呼び名の辞書 (呼び名と自由文) は `chrome.storage.local` — この端末の中だけです。**
> 以前は設定と同じ `sync` に置いていましたが、`sync` は 1 項目 8KB の上限があり、自由文を
> 足すと数十件で頭打ちになって**保存が黙って失敗する**ため、`local` へ移しました。
>
> - **別の PC の Chrome とは同期されなくなります。** 呼び名と自由文は、使う端末ごとに登録し直してください
> - 以前のバージョンで `sync` に保存されていた辞書は、**1 度だけ**この端末へ引き継がれます。
>   引き継ぎは**先に開いたほうの画面**(ライブチャット / この設定ページ)で走り、**結果は
>   その画面のコンソールに 1 行出ます** (`呼び名辞書を chrome.storage.local へ引き継いだ: N 件 (理由)` /
>   `呼び名辞書の引き継ぎはしていない: 理由`)。**失敗したときは警告が出て、次に開いたときに再試行します**
> - `sync` 側は消さないので、まだ更新していない別の PC からは辞書が消えません
>
> 呼び名の辞書には、リダイレクトを受けた相手のチャンネル URL が入ります。
> 1 行が持つのは **チャンネル URL / 呼び名 / リダイレクト返礼用の自由文 / 最後に受け取った時刻**に加えて、
> **「コメントに反応する」のフラグ (既定 OFF) / コメント返し用の自由文 (既定 空) /
> 照合用のチャンネル ID (`UC…` / 既定 空)** です。**どれもこの端末の中にだけ残ります。**

### 自由文 (`{msg}`) について

テンプレートに `{msg}` を入れておくと、**送信元ごとに登録した一言**が差し込まれます
(未登録の相手では `{msg}` が消え、前後の空白が 1 つに畳まれます)。

> ⚠️ **送信元の検知は推測を含みます。取り違えると、その人に宛てて書いた一文が
> そのまま別の相手への投稿に載ります。** 呼び名なら「誰かの名前」が出るだけですが、
> 自由文は宛先を間違えると内容そのものが事故になります。
> **取り違えて別の人に読まれても困らない内容だけを書いてください。**

> ✅ **自由文入りの文面は 2026-08-23 の実配信で通しました。** 検知 → 投稿 → 固定まで、
> 自由文が載った状態で通ることを確かめています。

### コメント返しについて (既定 OFF)

**リダイレクトの受信とは別の引き金です。**辞書で「コメントに反応する」を付けた人が
ライブチャットにコメントすると、その人のチャンネル URL を投稿します。

**動かすには 2 つとも自分で入れる必要があります。**

1. 設定の **「コメントに反応して投稿する」** を ON (**既定 OFF**)
2. 辞書の行を **▸** で開いて、**「コメントに反応する」** を ON (**既定 OFF**。
   リダイレクトを受けて自動で載った相手にも付いていません)

どちらか片方だけになっていると、設定画面がその旨を**常時表示**します
(「付けた人が 0 件です」/「N 人に付いていますが、このスイッチが OFF なので動きません」)。

| | |
|---|---|
| 固定 | **しません。**固定枠は 1 件しかなく、コメントのたびに上書きするとリダイレクト返礼の固定が流れるためです (固定モードの設定に関わらず固定しません) |
| 頻度 | 同じ配信・同じ人には **1 回**まで / 投稿の間隔は**最低 5 秒**。**この 2 つは設定にはありません。件数の上限はありません**(1 配信 20 件の上限は 2026-09-05 に撤廃)。⚠️ どちらも無条件ではありません — 5 秒の間隔は**チャット画面を開いている間**の話で開き直すと起点が戻り、「同じ配信」の判定は**配信 ID が取れている場合**の話です (下の「切り分け」) |
| 反応しない相手 | 辞書に載っていない人 / フラグが OFF の人 / **配信者自身** / スーパーチャット・メンバー加入・システムメッセージ |
| 反応しないコメント | **スイッチを入れた時点で既にチャットにあるコメント。**反応するのは、その後に新しく現れたコメントだけです。⚠️ **判定は分単位のタイムスタンプ + 10 秒の猶予**なので、**スイッチを入れたのと同じ分**のコメントがチャットの再構築で流れ直すと素通りすることがあります (**残る歯止めは「1 人 1 回」だけ**です) |
| 文面 | **リダイレクト返礼とは別のテンプレート。**`{name}` と `{url}` には**辞書に登録されている呼び名と URL** が入ります (コメント側の表示名は使いません)。`{msg}` に入るのは**コメント返し用の自由文**です |
| リダイレクト返礼との関係 | 同じ配信でその人へ**リダイレクト返礼を投稿済みなら、コメント返しはしません**。逆に、コメント返し済みでも**リダイレクト返礼は投稿します** (そちらが本命のため) |

#### 上限が効かない場合

上の表の「頻度」は無条件ではありません。**自動投稿の量に直結するので、ON にする前に読んでください。**

- **「最低 5 秒」は、同じチャット画面を開いている間の話です。** 直前の投稿時刻はメモリにしか
  持っていないため、**投稿の直後にチャットを開き直すと 5 秒未満で次が出ることがあります**
  ([src/post-queue.ts](../src/post-queue.ts))。
- **「スイッチを入れた時点で既にあるコメント」の判定は分単位です。** タイムスタンプ (`5:17 PM`) と
  監視開始から 10 秒の猶予で切っているので、**スイッチを入れたのと同じ分のコメント**が
  チャットの再構築 (ポップアウトの開き直し・フィルタ切替・仮想スクロール) で流れ直すと、
  **新しいコメントとして扱われることがあります。**⚠️ **残る歯止めは「1 人 1 回」だけです**
  (件数の上限は 2026-09-05 に撤廃しました)。最悪の場合、**辞書で「コメントに反応する」を
  付けた人数ぶん**が 5 秒間隔で流れます
  ([src/comment-detector.ts](../src/comment-detector.ts) / spec の AC9 に既知の穴として記載)。

#### 配信 ID が取れないとき

「同じ配信」の判定には、**チャット (または親の管制室) の URL から取れる配信 ID** を使います。
**管制室の埋め込みチャットでは ID を取れない**ことがあり、そのときは同じ配信かを判定できないため、
**判定材料が無いぶん長い方に倒します。**

**リダイレクト返礼・コメント返しとも**、「直近 6 時間」を同一配信の代わりに使います。

- 別の配信であっても、6 時間以内なら投稿しません (安全側)
- 逆に、**配信 ID が取れないまま 6 時間を超える配信では、同じ人への 2 回目や 21 件目が出ます**

なお、**手動の「↩ 返礼」はこの抑止の対象外です。**人が押した時点で意思表示なので、
同じ配信・同じ相手でも押せば投稿します (ただし同じ相手への投稿がいま走っている間だけは、その回を見送ります)。

**ポップアウトのチャット (`?is_popout=1&v=...`) を使えば配信 ID は確実に取れます。**
コンソールに `起動した {... streamId: '(不明)'}` が出ていたら取れていません。

#### チャンネル ID の取得 (`www.youtube.com` の許可が要る理由)

コメントから取れる投稿者の ID は `UC…` の形で、辞書の鍵 (`@ハンドル`) とは文字列が一致しません。
そのため **「コメントに反応する」を ON にした時点で、その人のチャンネルページを 1 回だけ読みに行き、
照合用のチャンネル ID を辞書に控えます。**取りに行くのは**まだ控えていない行だけ**で、
`.../channel/UC…` の形で登録されている行は**通信せずに** URL から読み取ります
(取得に失敗した行は、次に ON にし直したときにもう一度試します)。

- **この取得を行うのは設定画面だけです。ライブチャットの画面では行いません。**
- 取りに行くのは**辞書に登録されている URL** だけです。辞書を開いただけで全件は取りに行きません。
- **失敗しても他の機能は壊れません。**その行が**コメントに反応しなくなるだけ**で、
  リダイレクト返礼は今までどおり動きます。失敗した行には **⚠** が付き、
  行を開くと理由が出ます。辞書の上の**「未解決の行をまとめて再試行」**からやり直せます。
- **一度控えた ID は自動では取り直しません。**相手がハンドルを変えて別の人がそのハンドルを
  取得した場合、**照合は当たるのに投稿する URL は別人を指します。**呼び名・自由文と同じく、
  **人が直す前提**の項目です。

> ✅ **コメント返しは 2026-08-23 の実配信で通しました。**
> 登録者のコメントで投稿されること・固定されないこと・同じ配信で 2 回目が出ないこと・
> 自分の投稿を引き金に再投稿しないことは確かめています。
>
> ⚠️ **残る 1 点: チャットを開き直したときに、過去のコメントへ一斉投稿しないか。**
> 起動直後 10 秒の猶予・監視開始前のコメントをタイムスタンプで弾く・タイムスタンプが
> 読めなければ反応しない、の**3 重の歯止めがあり単体テストでも押さえています**が、
> **実 DOM では未確認**です。

## 3. 動いているか確かめる

1. 自分のテスト配信 (限定公開でよい) を開始する
2. **YouTube Studio のライブ管制室**を開く (`studio.youtube.com` → 「ライブ配信」)
3. 設定で「↩ 返礼」を出すようにしていれば、チャット部分の**右下にボタンが出ます**
   (出していない場合は、コンソールの `[shoutlink] 起動した {...}` で確認できます)

> `www.youtube.com` の watch ページやポップアウトでは**動きません** (意図的です)。
> ポップアウトを使う場合も Studio 側のものを使ってください。

### 投稿を試す

「↩ 返礼」→ 送信元チャンネルの URL か `@ハンドル` を入れる → **「投稿して固定」**。

同じパネルの **「固定だけ試す」** は、投稿せずにチャットの最後のメッセージを固定するだけの
切り分け用ボタンです。

設定した文面をそのまま試したいときは、**辞書の行を開いて出る「テスト送信」** も使えます。
開いているライブチャットのタブへ実際に投稿しますが、**投稿履歴には残らないので何度でも試せます。**
**固定はしません**(固定モードの設定に関わらず)。

## 4. 動かないとき

ログはブラウザの開発者ツールに出ます。**F12** → Console タブ。`[shoutlink]` で始まる行が
拡張のログです。

> **管制室に埋め込まれたチャットで見る場合は、Console 左上のコンテキスト選択 (既定 `top`) を
> `live_chat` のフレームに切り替えてください。** 拡張はチャットの iframe の中で動いているので、
> `top` のままだと何も出ません。チャットをポップアウトしている場合は、そのウィンドウで F12 を
> 押せばそのままです。

| 症状 | 見るところ |
|---|---|
| 「↩ 返礼」が出ない | 設定で「ライブチャットの右下に『↩ 返礼』を出す」が ON か (**既定は OFF**)。`studio.youtube.com` のライブ管制室を開いているか |
| コンソールに `この画面では動かさない:` が出る | 対象外の画面を開いている。Studio 側のチャットへ |
| 自動で投稿されない | 設定の「リダイレクトを自動検知して投稿する」が ON か。**同じ配信で同じ相手にはもう投稿済みではないか** (投稿履歴から「履歴を消す」を押せばすぐ試せます。再読み込みは不要です) |
| リダイレクトを受けたのに検知しない | Studio の表示言語が日本語か。検知は通知の**文言**に依存しています |
| `固定結果: unavailable` | 画面上の「固定」メニューが見つからない。**報告してほしい症状です** |
| リダイレクトを受けたのに反応しない | 診断ログを ON にして次のリダイレクトを待つ。通知の**文面をそのまま**添えて報告してください |
| コメントに反応しない | 設定の「コメントに反応して投稿する」と、辞書の行の「コメントに反応する」が**両方 ON か**。その行に **⚠** が出ていないか (チャンネル ID が未解決だと反応しません)。**ON にする前からあったコメントには反応しません** |
| 同じ人に 2 回目が出ない | 仕様です。**同じ配信・同じ人には 1 回**まで。**配信が変われば再び 1 回投稿します** — ただし**配信 ID を取れていない画面では、配信が変わっても 6 時間は投稿しません**(同じ配信かを判定できないため、履歴に 6 時間の下限をかけています)。コンソールの `起動した {... streamId: '(不明)'}` で分かります。**ポップアウト (`?is_popout=1&v=...`) を使えば配信 ID は確実に取れます** |
| 途中からコメント返しが出なくなった | **件数の上限は無くなりました** (2026-09-05 に撤廃)。止まっているなら「同じ配信・同じ人に 1 回」に当たっているか、辞書の行に ⚠ が出ていないかを見てください |

`固定結果` の意味:

| 値 | 意味 |
|---|---|
| `pinned` | 固定した |
| `skipped` | 意図的に固定しなかった (`off`、または `ifEmpty` で既に固定があった) |
| `unavailable` | 固定しようとしたが画面上の「固定」が見つからなかった |

### 報告するとき

[Issues](https://github.com/max-enterme/shoutlink/issues) へ。

> ⚠️ **コンソールのログや DOM を貼るときは、視聴者のチャンネル名・ハンドル・ID が
> 混ざっていないか確認してください。** リダイレクトの送信元だけ分かれば十分です。

## 5. やめる

`chrome://extensions` のカードで **「削除」**。設定も一緒に消えます。
配信に投稿されたメッセージは、チャットから手で消してください。
