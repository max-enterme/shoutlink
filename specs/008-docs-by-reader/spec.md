# 008 文書を読者別に整理する

## 目的
利用者・開発者・テスターが、自分に必要な案内へ README から進めるようにする。文書の移動前に参照検査を広げ、コードや仕様書内の参照切れも検出する。

## 背景 / 課題
docs 直下の10本に利用案内・開発手順・調査記録が混在する。install / setup-and-verify / for-testers は導入と設定の説明が重複する。005 の検査は主に Markdown リンクを見ているため、security-review の裸のパスや docs 外の参照は移動で壊れても分からない。composer の003調査記録への参照は既に存在しない。

## スコープ
- **含む**: 005 D2 の保留をこの feature で解消する。docs 外（specs / src / tests）から docs の md への参照と裸のパスの検査、既存不在参照の整理、読者別配置、重複案内のリンクへの集約、参照の更新。
- **含まない**: 拡張機能の動作・設定・画面の変更、サイトジェネレータの導入、調査記録の事実の書き換え、ストアへの再提出、仕様書の受け入れ条件や完了状態の変更。

## 受け入れ条件
- [ ] AC1: README の「利用者」「開発者」「テスター」の3区分から各読者の案内へ進める。移動後の docs の全 md に README から Markdown リンクで到達できる。
- [ ] AC2: install は利用者向け、setup-and-verify は開発者向け、for-testers はテスター向けの本文を持つ。一般の導入・設定は install を正本とし、他2本はリンクで案内する。開発ビルドの読み込み、配布 ZIP の読み込み、テストの事前条件と各テスト手順は各読者の文書に残す。
- [ ] AC3: check-links が既存の4種の検査に加え、specs/**/*.md / src/**/*.ts / tests/**/*.ts の docs md 参照と、README / docs / specs / src / tests の具体的な裸の docs md パスを検査する。参照元・行・対象を示し、不在・大小文字違い・不在アンカーで exit 1、正例で exit 0 を返す。
- [ ] AC4: 意図的な不在参照（テスト用の文字列・過去の未作成予定）は、理由と完全一致パスを持つ直後1行限定の明示除外だけで扱う。ファイル単位の除外や不在パスの全域許可は設けない。除外が効く範囲と範囲外の違反を自動テストで確かめる。
- [ ] AC5: 検査拡張と既存欠損の処理を B1、文書移動を B2 として別の塊にする。B1 は移動なしで合否コマンドが成功し、B2 は B1 の検査で古い参照の残存を検出できる。
- [ ] AC6: src/composer.ts の不在の003調査記録へのパスを削除する。200字上限の未検証という但し書きと定数の値は保持する。
- [ ] AC7: docs/store-submission.md の URL 群、docs/privacy-policy.md の配置、docs/index.html の配置・表示を維持する。index.html 内で移動先の md を案内している場合は自リポジトリ blob/main URL のパスだけ更新し、相対 md リンクに変えない。assets の配置は維持する。
- [ ] AC8: 型検査・全自動テスト・参照検査が成功する。履歴資料の本文はパス修正と検査の除外理由を除いて変えない。
