# 003 送信元ごとの自由文

> spec.md — フィーチャーの「何を・なぜ」。正本はこのテキストと GitHub(Feature issue)。

## 目的

返礼の文面に、**送信元ごとに違う一文**を差し込めるようにする。
「◯◯さんからリダイレクトありがとうございます! URL」の一律の文面から、
相手ごとに変えた一言を添えられる形にする。

## 背景 / 課題

現状、文面は `config.template` **1 本だけ**で、送信元によって変わるのは `{name}` に入る
表示名だけ([composer.ts](../../src/composer.ts))。呼び名の辞書
([directory.ts](../../src/directory.ts))は**呼び名 1 つしか持っていない**ため、
「この人にはこの一言」を持たせる場所が無い。

一方で、**人ごとの情報を持つ器はすでにある。** 辞書は正規化済みチャンネル URL を鍵にしていて、
リダイレクトを受けた相手は自動で載る。ここにフィールドを 1 つ足すのが最も素直で、
新しい保存先も新しい同一性の鍵も要らない。

### 併せて片付ける: 辞書の保存先

辞書は `chrome.storage.sync` に**配列まるごと 1 アイテム**で入っている。`sync` は
**1 アイテム 8KB 上限**で、自由文が加わると数十件で頭打ちになる。超えると `set` が reject し、
`guardAsync` が握るため**コンソールに 1 行出るだけで以後の登録が保存されない。**

これは [docs/security-review.md](../../docs/security-review.md) **S7** として既に挙がっていた
未対応の指摘(「件数上限か `local` への退避を検討」)で、自由文はその上限を一気に近づける。
**このフィーチャーで `local` へ移し、S7 を閉じる**(001 の tasks.md に残っている S7 の行も併せて処理する)。

## スコープ

- **含む**:
  - `DirectoryEntry` に自由文フィールドを追加(自動登録時は空)
  - テンプレートのプレースホルダ `{msg}` と、その差し込み
  - 200 字超過時の削り順を **自由文 → 表示名 → 末尾**へ変更
  - 辞書の保存先を `chrome.storage.sync` → `chrome.storage.local` へ移す(既存データの引き継ぎ込み)
  - 設定画面: 辞書テーブルの自由文欄、残り文字数、`{msg}` 不在の警告
  - 保存先と保存項目が変わることのドキュメント反映(プライバシーポリシー・公開ページ・テスター資料を含む)
- **含まない**:
  - **自由文の多言語化**(プレースホルダ名・UI 文言は 002 の対象。→ 降りる箇所 D2)
  - **配信ごと・時間帯ごとなど、送信元以外の条件での出し分け**(鍵が URL でなくなるので別問題)
  - **自由文のテンプレート化**(自由文の中で `{name}` 等を展開すること。→ AC9 で「しない」ことを固定する)
  - **`MAX_MESSAGE_LENGTH = 200` の実値の確定**(未検証のまま。→ plan.md R1)
  - **送信元ごとのプレビュー UI**(プレビューはサンプル 1 本のまま。→ AC7)

## 受け入れ条件

| # | 条件 |
|---|---|
| AC1 | テンプレートに `{msg}` を含めると、**送信元ごとに登録した自由文**が差し込まれる。<br>**差し込みの条件は D3 の決定に従う** — (a)(b) を採る場合、その条件をこの AC に追記してから実装する |
| AC2 | 自由文が未登録・空の送信元では、**その `{msg}` が消え、前後の空白が 1 つに畳まれる。**<br>例: テンプレート `{name}さん {msg} ありがとうございます! {url}` / 自由文なし → `れいさん ありがとうございます! https://…` |
| AC3 | 200 字を超える場合、**自由文 → 表示名 → 末尾**の順に削る。**自由文か表示名を削って収まる場合、URL は壊れない**(両方削っても収まらないときに末尾を切るのは現状どおり) |
| AC4 | 自由文を削るとき、**サロゲートペアを割らない**(絵文字が壊れた文字にならない)。**残せる長さが 10 字未満になるなら自由文ごと落とし**、結果は AC2 と同じ形になる |
| AC5 | 辞書が `chrome.storage.local` に保存される。**`local` にキーが存在しないときだけ** `sync` から引き継ぎ、**引き継ぎは 1 度きり**。<br>辞書を**全件削除した後に再起動しても、`sync` の古い辞書は復活しない**。<br>**移行に失敗した場合は移行済みフラグを立てず、次回起動で再試行する** |
| AC6 | 自由文は **1 件 200 字まで**。超える入力は設定画面で**保存されず、理由が表示される**。保存済みデータに 200 字超があれば正規化時に 200 字へ切り詰める |
| AC7 | 設定画面が、**テンプレートに `{msg}` が無いのに自由文が 1 件以上登録されている**とき警告を出す。<br>警告は**テンプレート欄の入力に追従して即座に出る / 消える**(保存を待たない)。表示先は**テンプレート欄の直下**。<br>プレビューは `{msg}` にサンプルの自由文が入った状態で表示される |
| AC8 | 設定画面の残り文字数は、**展開後の投稿文全体の長さに対する残り**を出す(自由文の 200 字に対する残りではない)。<br>展開に使うのは**その行のエントリの URL と、呼び名(未設定ならハンドル)**。テンプレート欄の編集(未保存)にも追従する。<br>**残りが負でも保存は妨げない**(投稿時に AC3 / AC4 の規則で削られる)。負であることが分かる表示にする |
| AC9 | 自由文の中に `{name}` `{url}` `{msg}` が含まれていても**再展開されない**(現状の 1 パス置換の不変条件を維持) |
| AC10 | 保存内容が壊れていても(自由文が欠損・文字列でない)`normalizeDirectory` が落ちず、空文字で埋まる |
| AC11 | 既存テストが通る。**`{msg}` を含まないテンプレートの出力が現状と 1 文字も変わらない** |

## メモ / 降りる箇所

- **D1: 実配信での通し確認。**
  自由文入りの文面が実際に投稿・固定されるところまでは、**実機でリダイレクトを受けないと確認できない**
  (SPEC-OPS §08)。しかも受けられるかは送る側に依存する
  ([security-review.md](../../docs/security-review.md) S8: 送る側に登録者 1,000 人以上の要件)。
  **これを feature 全体の main マージのブロッカーにすると、集約ブランチが他人待ちで滞留する。**
  T6 を待たずに main へ載せるか、載せるなら README / install.md に未検証である旨を書くかは、
  **人間が決める。エージェントが「確認したことにして」マージしない。**

- **D2: 002-i18n との調整。**
  本フィーチャーは `public/options.html` と投稿文テンプレートの説明文を触る。
  [002](../002-i18n/spec.md) は同じファイルを `data-i18n` 化し、UI 文言を `_locales/` へ移す。
  **どちらを先に main へ載せるか、`{msg}` を i18n の対象に含めるかは人間が決める。**
  002 が先に載る場合、T4 が足す UI 文言はすべて `_locales/` へのキー追加になる(plan.md 依存節)。
  **T7 の決着前に T4 を実装しない。**

- **D3: 誤検知したときの被害が、呼び名とは質が違う。**
  呼び名は取り違えても「誰かの名前」が出るだけだが、**自由文は特定の相手に宛てて書いた一文**で、
  宛先を間違えると内容そのものが事故になる。そして本 repo は送信元の取り違えを
  **実際に 2 回起こしている**([t1-findings.md](../../docs/t1-findings.md): 配信者自身を送信元と判定 /
  送信側バナーに反応して送信先へ返礼)。検知は今も推測を含む抽出に乗っている。
  取りうる方針と、それぞれの効く範囲・代償:

  | 案 | 効く範囲 | 代償 |
  |---|---|---|
  | **(a)** 投稿履歴に実績のある送信元にだけ差し込む | 初めて見る相手への誤配は全部防ぐ | 投稿履歴は **7 日で刈られ**(`POST_LOG_MAX_AGE_MS`)、**200 件で切られ**(`POST_LOG_MAX_ENTRIES`)、設定画面から消せる。→ **久しぶりの相手に自由文が出なくなる。履歴を消すと全員に出なくなる** |
  | **(b)** 起動時の初期走査由来の検知では差し込まない | 過去 2 件の取り違えのうち、**1 件目(初期走査でリスト全体を拾った件)だけ**。2 件目(送信側バナー)は observer 経路なので防げない | `RedirectEvent.origin` は今 `'auto' \| 'manual'` しか無く、[detector.ts](../../src/detector.ts) が 1 箇所で `'auto'` を埋めている。**初期走査由来かどうかを今のイベントは表現できない** → 型とプラミングの追加が要る |
  | **(c)** 実装は変えず、誤配のリスクを README / install.md で開示する | 何も防がない | 利用者の判断に委ねる。開示の記述を T5 に含める |

  **どれを採るかは人間が決める。** (a)(b) を採る場合、差し込み条件を AC1 に追記してから T3 を実装する。

- **`sync` 側の辞書は削除しない。**
  移行は `local` への**片方向コピー**にとどめる。`sync` のキーを消すと、まだ移行していない
  別 PC の Chrome から辞書が消え、復元できない。移行後は `sync` 側が更新されなくなるだけで、
  容量は増えない(新規の書き込みはすべて `local`)。**古いキーの掃除は本フィーチャーの対象外。**

- **辞書は端末間で同期されなくなる。**
  `local` へ移すことの代償。配信は 1 台で回す前提([config.ts](../../src/config.ts) の
  投稿履歴と同じ判断)なので許容するが、**利用者から見える挙動の変更**であり、
  README / install.md / privacy-policy.md / 公開ページに書かないと嘘になる。

- **既定テンプレートは変えない。**
  `{msg}` を既定に入れても、`normalizeConfig` は保存済みテンプレートを尊重するので
  **既存利用者には反映されない**(新規インストールだけ形が変わり、説明が二重になる)。
  代わりに「自由文はあるが `{msg}` が無い」を設定画面が警告する(AC7)。

- **GUI モック(SPEC-OPS §10)は併置しない。**
  既存の辞書テーブルに列を 1 つ足す範囲に収め、**レイアウトの決めどころを spec 側で潰した**
  (プレビューはサンプル 1 本のまま / 残り文字数の基準は AC8 で確定 / 警告の有無は AC7 で確定)。
  この判断は 2026-08-12 に人間が行った。
