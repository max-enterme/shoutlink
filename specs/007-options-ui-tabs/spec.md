# 007 設定画面をタブに分け、辞書を左右分割にする

> spec.md — フィーチャーの「何を・なぜ」。正本はこのテキストと GitHub(Feature issue)。

## 目的

設定画面を **4 タブ(基本設定 / 辞書 / 履歴 / 開発)** に分け、**辞書を左右分割(左=一覧 / 右=選択した 1 件の詳細)** にする。
左の一覧には**チャンネルのアイコン画像**を出し、誰の行かを顔で選べるようにする。

## 背景 / 課題

`public/options.html` は 7 つの `<fieldset>` が 1 枚に縦積みされており、**普段触らないもの(投稿履歴・診断ログ)と
毎回触るもの(辞書)が同じ縦スクロールに並んでいる。** 辞書は下から 2 番目で、開くたびにスクロールが要る。

辞書そのものにも 2 つの詰まりがある。

1. **行の中身が `▸` の展開でしか見えない** (004 T14)。自由文 2 本・「コメントに反応する」・チャンネル ID の状態・
   テスト送信は展開しないと出ず、**開くと下の行が押し下げられる。**複数人を見比べながら書けない。
2. **行がハンドル文字列でしか区別できない。** 辞書は「リダイレクトを受けた相手」が自動で積まれる名簿でもあり
   (`rememberSource`)、**自分で登録した覚えのない `@…` が並ぶ。**文字列だけでは誰なのか思い出せない。

配信中に開く画面なので、「探す時間」がそのまま配信の停止時間になる。

## スコープ

- **含む**:
  - `public/options.html` の骨格を 4 タブに組み替える。タブの外に警告バナーと保存バーを置く
  - `src/options/options.ts` の辞書描画を、行の展開(`expandedRows`)から選択(`selectedKey`)へ作り替える
  - 左の一覧にアイコン画像 / 未取得の行のモノグラム(頭文字の丸) / 絞り込み欄 / 「アイコンをまとめて取得」を足す
  - `DirectoryEntry` にアイコンのフィールドを足し、`src/channel-id.ts` の既存 fetch で `og:image` も拾う
  - 設定画面の DOM 配線を vitest(jsdom)で判定できるようにする
  - README / privacy-policy の通信の記述を、アイコン取得を含む形へ更新する
  - `public/options.html` に残っている「1 配信あたり 20 件までです。」(#127 で撤廃済み)を消す
    — 節をタブへ移すだけだと、書き直したファイルに古い文言が残るため
- **含まない**:
  - **ライブチャット画面 (content script / `src/main.ts` 以下) の変更。**この feature は設定画面だけを触る
  - **投稿・固定・検知・コメント返しの挙動の変更。**タブの割り当てが変わるだけで、機能の意味は変えない
  - **`manifest.json` の権限の変更。**アイコンの取得先 `yt3.googleusercontent.com` は
    `Access-Control-Allow-Origin: *` を返すので、`host_permissions` を増やさずに取得できる(2026-09-10 実測)
  - ダークモード対応 / ローカライズ(002 は `won't`)
  - Playwright 等のブラウザ自動化の導入(→ 「メモ / 降りる箇所」)
  - 辞書の保存先・同一性の鍵の変更(`chrome.storage.local` / 鍵は正規化済み URL のまま)

## 受け入れ条件

### タブ

- [ ] AC1: 設定画面が「基本設定」「辞書」「履歴」「開発」の 4 タブに分かれ、開いた直後は「基本設定」が選ばれている
- [ ] AC2: タブを選ぶと、そのタブの節だけが表示され、他の 3 タブの節は隠れる
- [ ] AC3: 基本設定タブに リダイレクト返礼 / コメント返し / 手動トリガー / 固定モード、辞書タブに 呼び名の辞書、
      **履歴タブに 投稿履歴**、開発タブに 診断ログ が入る
- [ ] AC4: `studio.youtube.com` でしか動かない旨の警告バナーは、どのタブを選んでいても表示される
- [ ] AC5: 保存ボタンはどのタブを選んでいても押せる。**開発タブの「診断ログ」を切り替えてから基本設定タブへ移って
      保存を押しても、その変更が保存される**(Config 7 項目をまとめて 1 回で保存する現行の意味を変えない)

### 辞書の左右分割

- [ ] AC6: 辞書タブは左右に分かれ、左に一覧・右に選択した 1 件の詳細が出る。**`▸` による行の展開は無くなる**
- [ ] AC6b: **左の一覧と右の詳細は、それぞれ独立してスクロールする。**
      片方を下まで送っても、もう片方の表示位置は動かない
- [ ] AC7: 左の 1 行に アイコン(丸) / 呼び名 / ハンドル が出る。呼び名が空の行はハンドルだけが出る
- [ ] AC8: 左の行を選ぶと、右にその行の詳細が出る。
      **何も選んでいないときは `← 左の一覧から選んでください` が出る**
- [ ] AC9: 右の詳細に ⚠ の理由(効かない行のときだけ) / ハンドル / 呼び名 / 「コメントに反応する」 /
      チャンネル ID の状態と再試行 / 自由文 2 本と残り字数 / テスト送信 2 ボタンと結果 / 削除 が、この順で出る。
      **左の一覧は表示専用で、入力欄を置かない**(呼び名の編集は右だけ)
- [ ] AC10: 「効かない行」(現行 `ineffectiveReasons` の判定)には左の一覧に ⚠ が出る。
      **その行を選ぶと、右の詳細に理由が文として出る**(現行はアイコンの `title` だけ)
- [ ] AC11: 一覧の絞り込み欄に文字を入れると、**呼び名かハンドルに一致する行だけが残る。**
      空にすると全件に戻る。**絞り込みで選択中の行が消えても、右の詳細はその行を出したままにする**
- [ ] AC12: 辞書が 0 件のときは、左に「まだ登録がありません」が出て、右は案内文のままになる
- [ ] AC13: 行を削除すると選択が外れ、右は案内文に戻る

- [ ] AC15: 「アイコンをまとめて取得」を押すと、**アイコンを控えていない行だけ**を順に取りに行く
- [ ] AC16: **辞書タブを開いただけでは 1 件も取りに行かない。**取りに行くのは AC14 の 2 経路と AC15 の
      ボタンを押したときだけ
- [ ] AC17: 控えたアイコンは `chrome.storage.local` に data URL で残り、**次に設定画面を開いたときは
      外部へ画像を取りに行かずに表示される**
- [ ] AC18: アイコンを控えていない行は、**呼び名(空ならハンドル)の頭文字 1 文字を描いた丸**が出る
- [ ] AC19: **アイコンの取得に失敗しても、チャンネル ID の解決は成功として扱う。**逆も同じで、

## メモ / 降りる箇所

- **`docs/assets/screenshot-1-options.png` の撮り直しは人手。** 実装が main に入った後、
  Chrome に `dist/` を読み込んで新しい設定画面を開き、同じ構図で撮り直して差し替える。
  自動撮影は Playwright の導入が要るため、この feature では行わない(下記)。
- **ブラウザ自動化(Playwright)は入れない。** 判定は vitest(jsdom)で行い、
  **見た目の崩れ・重なり・幅・左右の独立スクロール(AC6b)** を人手に残す(SPEC-OPS §05 が
  GUI feature に求めるブラウザ自動化を、この feature では見送る)。理由: 拡張を読み込むには
  headed Chrome が要り、CI に画面まわりの前提と不安定な失敗が増える。
  **CI の正本は 2026-09-09 の #128 で GitHub Actions から Jenkins(`max/shoutlink`)へ移っており、
  パイプライン定義は別リポジトリ `max-enterme/jenkins-pipelines` にある。**このリポジトリの
  変更だけでは CI に stage を足せないので、導入するなら向こうの変更とセットになる。
  **次に UI を触る feature で再検討する。**
- **ストアへの掲載更新の要否は、実装が入った後に確認する。** 権限(`manifest.json`)は変えないので
  再審査の説明は不要の見込みだが、掲載を更新する時に
  [docs/store-submission.md](../../docs/store-submission.md) の手順に沿って判断する。
- **アイコンの取得先が変わったら止まる。** `og:image` が `yt3.googleusercontent.com` を指さなくなる、
  または `Access-Control-Allow-Origin: *` を返さなくなった場合、**推測で `host_permissions` を足さない。**
  権限を増やすとインストール時の警告が変わるので、そこは人が決める。
